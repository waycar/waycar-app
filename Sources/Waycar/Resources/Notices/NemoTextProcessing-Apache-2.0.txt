Build selection and inventory
-----------------------------
Upstream build-xcframework.sh and .github/workflows/xcframework.yml build a
Rust staticlib (--release --features ffi,fst-engine; default features empty).
The four XCFramework slices contain seven target architectures:
  aarch64-apple-darwin
  x86_64-apple-darwin
  aarch64-apple-ios
  aarch64-apple-ios-sim
  x86_64-apple-ios
  aarch64-apple-ios-macabi
  x86_64-apple-ios-macabi

Resolved from v0.3.1 Cargo.lock using Cargo 1.99.1:
  cargo tree --locked -e normal --features ffi,fst-engine --target <target>
  cargo tree --locked -e normal,no-proc-macro --features ffi,fst-engine --target <target>
All seven target closures agree. The second command excludes host proc-macro
subtrees, which do not link into the Apple library. The full normal tree's
host-only entries are named separately below, with their notices retained
conservatively. Build/dev/wasm-only dependencies are not included.
Each registry .crate was SHA-256 verified against Cargo.lock before copying
its license/copyright texts. Line endings and trailing whitespace are normalized. Identical texts are reproduced once and referenced
by heading; copyright differences are retained, not merged away. rustfst's
.crate omits its licenses; those texts come from its repository root at the
.crate's checksum-verified .cargo_vcs_info.json commit:
https://github.com/Garvys/rustfst/tree/8e1391df1ef3dfb85e309dd4ee8af45251d28c9f
Legacy slash-separated license expressions are written as SPDX OR.
For the aggregate inventory, Waycar selects MIT where offered and Apache-2.0
otherwise. Additional Unicode-3.0 and compiler_builtins' combined MIT /
Apache-2.0 WITH LLVM-exception terms are retained. Alternative license texts
are also reproduced below; that does not require electing all alternatives.

Rust runtime in the staticlib
----------------------------
The release workflow selects moving "stable", without a version pin. The
checksum-matched iOS arm64 archive records /rustc/48a229ceaefd4985c50990b14116b6d856af0985/
source paths. That Rust commit's src/version is 1.98.1. Runtime notices use
that exact source revision, not the 1.99.1 used to inspect the Cargo graph:
https://github.com/rust-lang/rust/tree/48a229ceaefd4985c50990b14116b6d856af0985
This is binary/source evidence, not an assumption about today's stable.

Named runtime archive members: std, core, alloc, panic_unwind, unwind,
std_detect, rustc_std_workspace_alloc, rustc_std_workspace_core (Rust 1.98.1,
MIT OR Apache-2.0); compiler_builtins 0.1.160 (MIT AND Apache-2.0 WITH
LLVM-exception AND (MIT OR Apache-2.0)), including LLVM compiler-rt builtins.
LLVM compiler-rt source and credits at Rust's pinned llvm-project gitlink:
https://github.com/rust-lang/llvm-project/tree/52ed14fcd56afc30f9cccd8ca8ce237c2eef7e04/compiler-rt
The stdarch/portable-simd code incorporated by core/std_detect is covered by
Rust's MIT OR Apache-2.0 notices. Unicode tables also require Unicode-3.0.
The standard library incorporates backtrace-rs at d902726a1dcdc1e1c66f73d1162181b5423c645b
(MIT OR Apache-2.0), as pinned by the Rust source's library/backtrace gitlink.
Apple's system unwinder/libc is not a vendored GNU libintl or GNU libc.
