# Codex Backend

Status: v1 built (epic E1). Fifth Backend: `HostBackend.codex`, shown as "Codex". Evidence below is Codex 0.167.1 on Linux x64, not a promise of compatibility with later releases. The executable pin and artifact hashes live only in `scripts/ci/codex-contract.py`.

Codex's CLI runs on a shared background server (the app-server daemon) by default whenever one is running; `--no-daemon` opts out. One daemon holds every Codex thread on the Host, desk TUIs included, and serves JSON-RPC over a WebSocket on a Unix control socket. Waycar reaches that socket through OpenSSH direct-streamlocal, as it reaches herdr's (ADR 0011). Like Ultimate (`ultimate-backend.md`) it is chat-first: a thread has a transcript and structured approvals, never a terminal of its own; a pane that shows the thread's TUI is linked to it instead (section 2).

## 1. Load-bearing Codex facts

- **X1 — Detection:** `--version` prints `codex-cli <version>`; absent `app-server daemon version` exits 1 with empty stdout, starts no process and creates no socket (it does create `CODEX_HOME/tmp/arg0-linux`). Codex 0.167.1, live: `detection`.
- **X2 — Socket isolation:** the advertised `CODEX_HOME/app-server-control/app-server-control.sock` is a symlink into canonical `/tmp/codex-daemon-<euid>/<sha256(canonical advertised path)>`; a sibling `<hash>.lock` protects startup. HOME/TMPDIR cannot relocate that physical directory; unique canonical CODEX_HOME paths isolate endpoints. Codex 0.167.1, live: `daemon_start`; source review: tag `rust-v0.167.1`, `uds/src/daemon_directory.rs`, `app-server-transport/src/transport/unix_socket.rs` (`protected_socket_path`).
- **X3 — Managed lifecycle:** start bootstraps from a complete npm package, not a bare executable, and survives the CLI's exit; stdout is one JSON object with `status`, `backend`, `socketPath`, `cliVersion`, `appServerVersion` and managed-package fields. Initial `started` includes `pid`; repeated `alreadyRunning` and `version`'s `running` omit it. Codex 0.167.1, live: `daemon_start`; package requirement also source review: tag `rust-v0.167.1`, `app-server-daemon/README.md`.
- **X4 — Updater:** scratch daemons disable automatic updates via `CODEX_HOME/app-server-daemon/settings.json`, `updater.autoUpdateEnabled=false`; lifecycle serialization uses CODEX_HOME, separately from X2's physical startup lock. Codex 0.167.1, source review: tag `rust-v0.167.1`, `app-server-daemon/README.md`; all live scenarios supply that setting.
- **X5 — Wire:** the Unix socket accepts a tokenless RFC 6455 upgrade with status 101 and correct `Sec-WebSocket-Accept`, no unsolicited extensions; masked/fragmented client text and ping/pong work. Each received text message contains one JSON object, without `jsonrpc`; requests with `jsonrpc:"2.0"` are also accepted. Codex 0.167.1, live: `websocket`.
- **X6 — Admission:** requests before `initialize` return `{error:{code:-32600,message:"Not initialized"},id}`; initialization takes `clientInfo` and optional `capabilities.experimentalApi`, returns `userAgent`, `codexHome` and platform metadata. The subsequent `initialized` notification is accepted but not required for calls. Codex 0.167.1, live: `initialize`.
- **X7 — Launch:** `thread/start {cwd}` returns a thread id/cwd and subscribes its caller; `thread/started` reaches a second initialized connection that never subscribed to that thread. Codex 0.167.1, live: `thread_start`.
- **X8 — Inventory:** `thread/loaded/list` returns ids in `data`; `thread/read` returns `thread` with id, cwd, nullable name, preview, status, source, parentThreadId, ephemeral, createdAt and updatedAt. A new API-created thread is idle, non-ephemeral, source `vscode`, with no parent/name and integer timestamps. Codex 0.167.1, live: `loaded_read`.
- **X9 — Routing:** `turn/start` text produces `turn/started`, `item/started`, `item/completed` and `turn/completed` for subscribers; non-subscribers receive `thread/status/changed` active→idle, not turn/item traffic. Codex 0.167.1, live: `turn_round_trip`.
- **X10 — History:** `thread/turns/list` defaults to summary items (`itemsView:"summary"`), including `userMessage.content` text parts and `agentMessage.text` with string item ids; command items are not in that default summary. Paging exposes `nextCursor` and `backwardsCursor`; opaque next cursors work with `limit` and `sortDirection`. Codex 0.167.1, live: `turn_round_trip`; command-summary exclusion observed during `approval_race` investigation.
- **X11 — Steer:** `turn/steer {threadId,expectedTurnId,input}` during an active turn returns that turn id and persists the additional text in history. Codex 0.167.1, live: `steer`.
- **X12 — Interrupt:** `turn/interrupt {threadId,turnId}` results in `turn/completed` with status `interrupted`. Codex 0.167.1, live: `interrupt`.
- **X13 — Disconnect:** losing the turn's only subscriber does not cancel it; it completes, status reaches an observer, and a new connection can resume/read the completed turn and agent reply. Codex 0.167.1, live: `disconnect_mid_turn`.
- **X14 — Approval:** command approval broadcasts active status with `activeFlags:["waitingOnApproval"]`; only subscribers get `item/commandExecution/requestApproval` (id, thread/turn/item ids, cwd, shell-wrapped command and availableDecisions). The mock's command is `/bin/bash -lc 'echo waycar-tool-ok'`; available choices include `accept`, an exec-policy amendment object and `cancel`. Codex 0.167.1, live: `approval`, `approval_race`.
- **X15 — Reconnect approval:** disconnecting leaves approval pending; a new connection's `thread/resume` replays the same request/id once, and `{id,result:{decision:"accept"}}` resolves it and lets the turn finish; `serverRequest/resolved` identifies thread/request ids. Codex 0.167.1, live: `approval`.
- **X16 — Approval race:** two subscribed connections can see the same approval id; the first accept executes the command once, the other receives `serverRequest/resolved`, and a late valid cancel neither reverses the decision nor breaks its connection. Codex 0.167.1, live: `approval_race`.
- **X17 — Names/reconciliation:** `thread/name/set` broadcasts `thread/name/updated` with `threadName`; after a first turn, `thread/list {sortKey:"updated_at"}` returns names in descending update order. **An empty named launch is absent from thread/list**: before its first turn, use loaded ids plus `thread/read` (which already has its name), not list alone. Codex 0.167.1, live: `thread_name`.
- **X18 — Unload:** with no subscribers and no active turn, `thread_unload_delay_secs` elapses, `thread/closed` broadcasts, loaded/list drops the id, read still returns durable metadata with status `notLoaded`, and resume reloads it for another turn. The check sets 2 s; the default is 60 s. Codex 0.167.1, live: `unload`; default source review: tag `rust-v0.167.1`, `core/src/config/mod.rs`.
- **X19 — TUI coexistence:** a real `codex resume <id>` under a PTY joins the daemon and keeps the thread loaded beyond the idle-unload delay; `codex --no-daemon resume <id>` renders the same history but does not keep the daemon's thread loaded. Codex 0.167.1, live: `tui_joins`.
- **X20 — Stop:** `daemon stop` prints one JSON object with status `stopped`; after graceful shutdown the advertised and physical sockets disappear, and `daemon version` is again nonzero with empty stdout. The check allows 5 s shutdown grace; 0 s forces termination and can leave socket/lock files. Codex 0.167.1, live: `daemon_stop`; zero-grace residue observed during contract development.
- **X21 — Errors:** unknown method, malformed parameters and `turn/start` on an unknown thread return correlated `{id,error:{code:-32600,message:<string>}}`, not the conventional JSON-RPC -32601/-32602 distinction. Codex 0.167.1, live: `errors`.
- **X22 — Canonical cwd:** `thread/start` stores the canonical cwd (`/tmp` → `/private/tmp` on macOS), so the requested path is not launch identity. Codex 0.167.1, live on macOS: `CodexTransportE2ETests`.
- **X23 — TUI resume:** resuming an unloaded thread with `codex resume <id>` broadcasts `thread/status/changed`, not `thread/started`. Read an unknown thread once on its first loaded status; do not subscribe merely to list it. Codex 0.167.1, live on macOS: scratch HOME, mock model and tmux, observed from a separate initialized WebSocket client (2026-11-11).

- **X24 — Thread origin:** `source` is `vscode` for both a plain desk TUI joining the daemon and an API-created thread, so it cannot distinguish their owners. The TUI sends `threadSource: "user"`; Waycar sends `threadSource: "waycar"`. The explicit value reads back from `thread/read` and survives idle unload and reload. `threadSource` is a free string (`user`, `subagent`, internal roles and feature names), not the older `source` enum. Codex 0.167.1, live: `tui_joins`, `thread_source`; source review: `rust-v0.167.1`, `tui/src/app_server_session.rs` (`thread_start_params_from_config`) and `protocol/src/protocol.rs` (`ThreadSource`).

- **X25 — Fresh TUI history:** the normal state DB exists, but a new TUI thread can appear before its paginated metadata row is indexed. During that startup window `thread/turns/list` can report “not materialized yet” or `-32601` “list_turns is not supported yet”; once the row is present it succeeds. This is not a scratch-config DB disablement and can affect real Hosts. On a server refusal Waycar tries `thread/read {includeTurns: true}`, whose compatibility turns are oldest-first, through the same transcript builder; both routes keep only the newest 200 turns, and paging stops after four pages. Before materialization both calls may still refuse, leaving the normal transcript refresh to retry. Codex 0.167.1, live: normal scratch HOME, PTY TUI, read-only state-DB inspection and `tui_joins` history assertion; source review: `app-server/src/request_processors/thread_processor.rs` and `thread-store/src/local/thread_history/read.rs` (`validate_thread_for_paginated_reads`).

## 2. Shape

Decisions: Mike, card 1158 (pick 4b) and card 1224 (1a–6a), 2026-11-11.

- **Detection** (X1): the one detection exec runs `codex --version` and `codex app-server daemon version`; exit 1 means no server. Nothing else, so detection starts nothing. `CodexPresence` carries the path, version and, for a running server, its socket. Only a running server at or above the 0.167.0 floor gets a projection (`HostBackendPresence.codexRunning`); an older CLI asks the user to update Codex. An installed/stopped server is checked again on connection or foreground, so a server started elsewhere appears then.
- **Starting** (memory `no-auto-start-host-services`): Waycar never starts the daemon on its own. Host detail shows "Codex server running" or "Codex server not running". The stopped state with **Start Codex server** shows only there and in New Agent › Codex, never as a Console banner or row (card 1224 3a): Codex is on most Hosts and its TUI never starts the server. The start runs `codex app-server daemon start`, in the macOS login session as a one-shot launchd job like Start Herdr Core, because every command Codex runs inherits the daemon's environment (X3, daemon README).
- **Transport** (`Sources/Waycar/Transport/Codex/`): `CodexWebSocket` (minimal RFC 6455 client, no extensions, X5) over a direct-streamlocal channel in the `.ordinaryForwarding` admission class, so herdr's single `.events` slot and tmux/core's session budget stay free; `CodexRPCClient` (requests, notifications, server requests, no `jsonrpc` field); `CodexTransport` (the Transport). One long-lived connection per Host. A skipped WebSocket frame throws cancellation, and `CodexRPCClient`'s send catches keep it local to that call; letting it escape leaves a closed client for the next write.
- **Inventory** (X7, X8, X9, X18): `thread/loaded/list` plus `thread/read` per id at open; then the notifications every connection gets: `thread/started`, `thread/closed`, `thread/status/changed`, `thread/name/updated`; the first status for an unknown loaded thread reads it once (X23). Only loaded top-level threads are Agents (card 1224 2a): not ephemeral, no parent thread. A thread that unloads (no client, idle for `thread_unload_delay_secs`, 60 s by default) leaves the list and becomes a Closed Session, unless it is unnamed and has no turns (nothing to resume). Pane id `codex:<threadId>`, one Workspace per working directory. **Show Codex threads** is on by default per Host. Resume from Closed Sessions reloads the thread and opens a linked terminal on a Host with a visible terminal runtime, as for New Agent.
- **Status**: active with `waitingOnApproval` or `waitingOnUserInput` is Blocked, active is Working, idle is Done once this connection saw it finish (until the user opens it) and Idle otherwise; `systemError` is Unknown. Nothing comes from Waycar's Status Hooks: daemon-run hooks carry the daemon's environment (probe 8), so the tmux hook guard keeps dropping them.
- **Approvals** (X14–X16): a Blocked thread is subscribed with `thread/resume {excludeTurns: true}`, which replays its pending server requests once. Command and file-change approvals show on Chat Mode's **Needs your OK** card with Allow (`accept`) and Cancel (`cancel`, Esc in the TUI). File-change paths come from the matching item in full turn history; if unreadable, the card offers Cancel only and asks for review on the Host. `item/tool/requestUserInput` shows as a **Needs your answer** card. Answers need a live connection and are never queued. `serverRequest/resolved` removes one answered elsewhere; the first answer wins. Requests Waycar does not model stay answerable in the terminal. Seam: `Transport.pendingAgentRequests` / `answerAgentRequest`.
- **Subscriptions**: a thread this connection resumed, started or prompted stays subscribed until the connection closes, so it stays listed while the phone is connected. Nothing is resumed only to list it.
- **Chat** (X10–X13, X25): `thread/turns/list` summary items, falling back to `thread/read {includeTurns: true}` on a server refusal: user prompts, each turn's final reply, and a failure card for a turn that ended in an error. Send is `turn/start`, or `turn/steer` with the active turn id while one runs; Stop is `turn/interrupt`.
- **New Agent › Codex** (pick 4b, card 1224 4a, 5a): `thread/start` in the chosen folder, named with the Agent's name (`thread/name/set`), with an optional first message, then `codex resume <threadId>` (daemon mode, no `--no-daemon`) in a new Workspace on the Host's lead visible terminal runtime (Herdr TUI, then Herdr Core, then tmux); chat-only on a Host with none. The Chat Mode toggle works as on every runtime: on sends the Chat Prompt as `developerInstructions` with the Settings › Chat Mode Codex model and Quick thinking. Off still opens the thread as a chat, without those settings. A lost answer is reconciled by the thread's name (the Launch Tag) among loaded threads tagged `threadSource: "waycar"`, preferring an exact folder match and otherwise the newest `createdAt`, not `thread/list`, which omits a thread before its first turn (X17, X22). If naming was lost too, adopt only the newest unnamed, turn-less thread tagged `threadSource: "waycar"` in the same folder (including macOS `/private/tmp` and `/private/var` aliases), then name it before returning.
- **One card per session** (card 1224 1a): the thread card is the Agent. A pane known to show that thread is hidden from its terminal backend's list and opens from the card's Show Terminal. Waycar knows the link from its own launch, else from `codex resume <id>` in the pane's command line, else from a one-to-one same-folder match between an unlinked daemon-mode Codex pane and an unlinked TUI-started thread (`threadSource: "user"`, X24); never a Waycar-tagged or unknown thread. Without a sure link both cards show. Codex launches through Herdr TUI, Herdr Core or tmux keep `--no-daemon`, so they never join the daemon and never show twice. A server detected at the 0.167.0 floor proves the flag (`AgentLaunchBuilder.codexSupportsNoDaemon`); an older Codex is probed for it, never assumed to lack it.
- **Push** (card 1224 6a): Host Tools 2.4.0 posts needs-your-OK and Done (with the final reply) for Codex server threads as `codex:<threadId>`, never as a pane. The installed Codex hook commands stay unchanged; `codex_enabled: false` in `notify.json` silences these notifications. Live Activities and Apple Watch include the Console's Codex thread rows.

## 3. Risks

- The daemon contract "may change" (daemon README). The contract check fails CI on drift; the app parses leniently.
- The daemon updates itself hourly by default and restarts, interrupting turns; Waycar's connection drops and reconnects, and a turn may end interrupted.
- Desk TUIs started before the daemon run on an embedded server and never appear until restarted.
- A desk TUI's thread is joined to its pane only by command line or a unique folder; two plain `codex` TUIs in one folder show as two cards each.
- Hosts need `AllowTcpForwarding local` or `yes`, as for herdr.
