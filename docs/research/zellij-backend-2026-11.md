# Zellij: probe for a terminal Backend (Nov 2026)

Status: probe and assessment; the build follows in [`../design/zellij-backend.md`](../design/zellij-backend.md). It follows the runtime scan in [`runtime-alternatives-2026-11.md`](runtime-alternatives-2026-11.md) (Mike's order: Codex, OpenCode, then Zellij).

**Method.** Zellij **0.46.0** (`zellij-x86_64-unknown-linux-musl.tar.gz` from the GitHub release; the release's `.sha256sum` hashes the extracted binary: `afb6bfb5f9fdc3d9e9d094ce21866bc99d37073a5fbe75bb612e21fc9b96033d`, matched), plus 0.45.1 and 0.44.3 for the floor, probed on **2026-11-12** in a scratch Ubuntu 24.04 container on a throwaway Docker host (2 CPUs, removed afterwards). OpenSSH 9.6p1 to localhost (`ssh -T` for non-PTY execs, `ssh -tt` for attaches), tmux 3.4 private servers as stand-in terminals (desk 200x50, phone 80x30), mosh 1.4.0, Claude Code 2.1.296 against the harness lab's mock model (`scripts/harness-lab/mock/server.js`). No accounts. Source review of the `v0.46.0` tag (commit of 2026-11-11). "Live" means a command run with its output recorded; "source" a read of the tag.

## Load-bearing Zellij facts

- **Z1 — Machine interface over a non-PTY exec.** `zellij -s <session> action list-panes -j`, `list-tabs -j`, `list-clients`, `dump-screen`, `write-chars`, `paste`, `send-keys`, `new-tab`, `new-pane`, `close-pane`, `rename-pane`, `rename-tab-by-id` and `zellij ls -n` all work over `ssh -T` with no tty. Live.
- **Z2 — Pane records.** `list-panes -j` (a pretty-printed, multi-line JSON array: the contract check found it, the probe had read it through `jq -c`) gives per pane: `id` (a number, unique within its kind: terminal and plugin panes each count from 0, addressed as `terminal_N` / `plugin_N`), `is_plugin`, `tab_id` (stable), `tab_position`, `tab_name`, `title` (the pane's name if set, else the program's terminal title), `pane_command` (foreground command with arguments, e.g. `claude --permission-mode default`), `pane_cwd`, `terminal_command` (the launch command line verbatim, null for the default shell), `exited`, `exit_status`, `is_held`, `is_floating`, `is_suppressed`, `is_focused`, geometry (`pane_columns`, `pane_rows`, content variants), `cursor_coordinates_in_pane` (moves on every keystroke), `program_status` (Z9), `attention` (Z10) and `command_state`. No tty, no pid. Plugin records omit `pane_command` and `pane_cwd`. Zellij's own bars are plugin panes (`zellij:bars`, `tab-bar`, `status-bar`, the welcome `configuration`). Right after `attach -b` the command can print nothing with exit 0 until the session is up. Live, and pinned by `scripts/ci/zellij-contract.py`.
- **Z3 — Tabs and sessions.** `list-tabs -j` gives `tab_id`, `position`, `name`, `active`, `viewport_rows/columns`, `display_area_rows/columns`, `other_focused_clients` (client ids viewing the tab) and a per-tab attention roll-up. `list-clients` prints a table `CLIENT_ID ZELLIJ_PANE_ID RUNNING_COMMAND`. `zellij ls` has no JSON: `-n` prints `<name> [Created <age> ago] ` per live session and adds `(EXITED - attach to resurrect)` for closed ones; `-s` prints names only, closed ones included, unmarked. Exit 1 with `No active zellij sessions found.` when there are none. Sessions are addressed by name only (`-s <socket id>` is refused). Live.
- **Z4 — Cost.** One `zellij action list-panes -j` takes 16 ms wall on the Host (4 ms user, 11 ms sys in the client; about 2 ms of server CPU, 13 ticks over 50 calls); `list-tabs` and `ls` 15 ms. Each call is one process; there is no batching of actions in one invocation. Live.
- **Z5 — No push for topology.** Only plugins receive tab, pane and session events. `zellij -s S subscribe -p <pane…> -f json` streams full viewport renders over a non-PTY exec (`{"event":"pane_update","is_initial",…,"viewport":[…]}`): 43 events and 460 KB in 9 s of one Claude turn at 200x48, a screen feed, not a status feed. With `cursor_coordinates_in_pane` removed, `list-panes -j` changed once in 20 half-second polls while idle and 3 times in 16 polls during a turn, so a Host-side loop that prints only changes sends little. Live.
- **Z6 — Detection starts nothing.** `zellij --version` (7 ms), `ls`, `ls -n`, `ls -s`, `list-aliases`, and `action list-panes|list-tabs|dump-screen`, `subscribe` and `run` against a missing or closed session start no server: `There is no active session!` or `Session 's3' not found. The following sessions are active: …`, exit 1. Only `zellij attach <closed session>` (resurrects it), `attach -b`, `attach -c`, bare `zellij` and `zellij -s <name>` with no subcommand start one. Live.
- **Z7 — Sizes are per tab.** A tab takes the smallest size among the clients viewing it (0.45.0+, CHANGELOG #5133; live on 0.45.1 and 0.46.0): a phone at 80x30 on the desk's tab shrank the desk's view to 80x30; with the phone on another tab the desk kept 200x48. A tab nobody views keeps its last size. On 0.44.3 the whole session took the smallest client (CHANGELOG). Live.
- **Z8 — Attach lands on the desk's tab; CLI focus follows the last typist.** A new client starts on the active tab of the lowest-numbered client (`screen.rs` `add_client`: `active_tab_ids.iter().next()`, source), so it shrinks the desk's tab at once. Focus is per client, but a `zellij action` from the CLI (`go-to-tab-by-id`, `focus-pane-id`) acts on `last_active_client`, the last client that sent a key (`route.rs`, source); with the desk last, `go-to-tab-by-id 2` moved the **desk** (live). Recipe that moves only the phone and never resizes the desk (live on 0.46.0; the mode part also on 0.45.1):
  1. Request the attach PTY oversized (400x150): the desk's tab keeps the desk's size, because the smallest client wins.
  2. Exec `zellij attach S options --default-mode normal` (a per-client option: the desk keeps its own mode).
  3. Once it has drawn, send Ctrl g (`0x07`): Zellij consumes it (Normal to Locked) in about 50 ms, nothing reaches the pane, and the phone becomes `last_active_client`.
  4. `zellij -s S action go-to-tab-by-id T` then `focus-pane-id terminal_N` (exits 2 with `Pane Terminal(N) is already focused` when it is).
  5. Resize the PTY to the phone. The desk stayed on its tab at 200x48 throughout, and later typing on the phone reached the pane.

  A desk keystroke between steps 3 and 4 makes the desk the target of step 4. The probe's first recipe (`--default-mode session`, then Esc) also moves only the phone, but the contract check found that a client whose current mode differs from its default mode swallows ordinary typing (Normal keys are written to the pane only when Normal is the client's `default_input_mode`; same for `--default-mode locked` then Ctrl g), and a lone Esc takes about 1 s to parse on a PTY nobody answers queries on. Contract-proven on 0.46.0, 3 fresh sessions each.
- **Z9 — Agent-reported status (OSC 7501).** Zellij 0.46.0 parses `ESC ] 7501 ; key=value:key=value ST` (`zellij-server/src/attention/program_status.rs`, source): `state` `idle|working|done|blocked|error|clear`, `kind` `permission|question|auth`, `app`, `msg`/`title` base64, `progress`, `id` for nested records; it answers `ESC ] 7501 ; ?` with `?:states=idle,working,done,blocked,error:kinds=permission,question,auth`. The records appear in `list-panes` as `program_status: [{id, state, kind, progress, app, title, msg, updated_ms}]` (root record `id: null`). Claude Code 2.1.296 reports by itself: `Idle` at start, `Working` on submit, `Working` with `msg: "Running echo waycar-tool-ok"` during a tool call, `Done` at turn end, and `Blocked` `kind: Permission` `msg: "approve Bash: touch /tmp/waycar-tool-mutate && echo waycar-tool-ok"` on a permission prompt (live). A record written to the pane's tty by an outside process is taken the same way (`printf '\033]7501;state=working:app=waycar\033\\' > /dev/pts/N`; live), so Waycar must not do it: that write can land inside a frame the agent is drawing. Before 0.46.0 `program_status` is null.
- **Z10 — `attention` is Zellij's inbox view, not status.** `attention.status` (`Idle|Working|NewOutput|Quiet|Done|Failed|NeedsYou`, `source` `ProgramStatus|Bell|CommandPane|ForegroundProcess|…`) clears Done to Idle once a client has seen the pane: a Done pane on the tab the phone was viewing read `attention: Idle` while `program_status` still said `Done`. Read status from `program_status`'s root record. Live.
- **Z11 — Pane environment.** Programs in a pane get `ZELLIJ=0`, `ZELLIJ_PANE_ID=<n>` (the terminal pane number) and `ZELLIJ_SESSION_NAME=<name>` (read from `/proc/<claude pid>/environ`), plus whatever environment the server had (a session started from a tmux pane hands every pane `TMUX` and `TMUX_PANE`). `rename-session` keeps the old `ZELLIJ_SESSION_NAME` in running panes, and the old name no longer resolves. Live.
- **Z12 — Input into a pane without attaching.** `write-chars --pane-id terminal_N "<text>"` types; `paste --pane-id terminal_N "<text>"` brackets only when the program asked for bracketed paste (`cat -v` received plain `A\nB`; Claude kept a two-line paste in its composer, unsent); `send-keys --pane-id terminal_N Enter|Esc|"Ctrl u"` sends named keys. Paste then Enter as two back-to-back calls submitted exactly once in Claude, as did paste, 0.3 s, Enter. Each call 16–20 ms on the Host. Text rides argv, so one draft is bounded by Linux's 128 KiB per-argument limit (`MAX_ARG_STRLEN`; not measured). Live.
- **Z13 — Launching.** `new-tab --no-focus --name N --cwd D -- <cmd…>` prints the new tab's id; `new-pane --tab-id T --name N --no-focus --cwd D -- <cmd…>` prints `terminal_N` (`--name` becomes the pane title until renamed). There is no environment flag; the command line carries it (`bash -lic "env WAYCAR_LAUNCH=<tag> claude; exec bash -l"` ran claude, and `terminal_command` showed that line verbatim, so the Launch Tag is findable). A command pane whose program exits is held unless `--close-on-exit`. Live.
- **Z14 — `new-tab` fails with no client attached.** With no client in the session, `new-tab` prints a tab id and exits 0 but applies no layout (`Failed to apply layout: Not enough room for panes` in `zellij.log`): a session attached once gets an empty 0x0 tab with no pane; a session made by `attach -b` and never attached (50x50) gets nothing. Same on 0.45.1. `new-pane` into an existing tab works headless. `zellij attach -b NAME -- <cmd>` (0.45.1+) makes a background session running `<cmd>` in about 0.3 s, at 50x48 until a client attaches. Live.
- **Z15 — Closed sessions.** A session is listed `(EXITED - attach to resurrect)` after `kill-session` once Zellij has serialized it (about a minute after start; a session killed seconds after creation is not listed). Its saved layout keeps `pane command="claude" { start_suspended true }` (the foreground command, without the wrapper). `set-resurrect-command --pane-id terminal_N -- <cmd…>` (0.46.0) sets what resurrection runs for that pane; `delete-session <name>` removes a closed session. Live.
- **Z16 — Detach.** Ending the SSH channel (SIGHUP) ends `zellij attach` with no orphan, and the tab returns to the remaining clients' size. Under mosh-server the client lives as long as mosh-server (killing mosh-server ended it), so Waycar's mosh shutdown handshake and `MOSH_SERVER_NETWORK_TMOUT` cover it. `zellij attach` under `mosh-server new -s … --` renders and resizes. Live.
- **Z17 — Socket directory.** `$ZELLIJ_SOCKET_DIR`, else `$XDG_RUNTIME_DIR/zellij`, else `$TMPDIR/zellij-<uid>`, then `contract_version_1/` (0.46.0; source `zellij-utils/src/consts.rs`). Sockets are named by a random session id, mapped to names in `~/.cache/zellij/contract_version_1/session_index.sqlite`. An SSH exec on macOS gets the same per-user `TMPDIR` as the GUI (`/var/folders/…/T/`, equal to `getconf DARWIN_USER_TEMP_DIR`; checked on macOS 27.2.1), so desk sessions are visible over SSH. Live (Linux) and live env check (macOS).
- **Z18 — Versions.** The CLI surface Waycar uses (`list-panes`, `--pane-id`/`--tab-id` on actions, ids returned by `new-tab`/`new-pane`, `subscribe`) arrived in 0.44.0 (2026-03-23, CHANGELOG #4690, #4814, #4846); `--no-focus` on `new-tab` and per-tab sizes in 0.45.0 (0.44.3 rejects `--no-focus`); OSC 7501 status, `set-resurrect-command` and the version-independent `contract_version_1` socket directory in 0.46.0 (2026-11-11). Servers before 0.46 live in per-version socket directories a newer CLI cannot see, and the 0.44/0.45 `ls` lists 0.46 sessions under their socket ids. Live and CHANGELOG.
- **Z19 — Availability.** Not packaged by Ubuntu, Debian, Fedora, EPEL or Rocky (repology, 2026-11-12). Homebrew 0.46.0 on release day; Arch, nix-unstable, openSUSE Tumbleweed, MacPorts, FreeBSD 0.45.1. Most Linux users run the static release binary (`~/.local/bin`, `cargo install`). The plugin API (`zellij-tile`) has breaking changes in the unreleased notes; the CLI has only grown.

## What this means

- Inventory: one non-PTY exec running a POSIX loop over `ls -n` and `list-panes -j` per session, printing a snapshot only when it changed (Z4, Z5). No Host Tools needed.
- Status: `program_status`'s root record first (Z9, Z10), hook state second, screen detection last.
- Attach: the Z8 recipe, checked after step 4 with `list-clients`, falling back to the whole session.
- New Agent: `new-tab` when a client is attached, a background session otherwise (Z14); the tag rides the command line (Z13).
- Closed Sessions: Zellij's own closed sessions, resumed only on a tap (Z6, Z15).
