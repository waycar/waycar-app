## 1. Framed mode over `hc connect`, no pty

**Setup** (what an SSH exec channel without pty gives): the probe runs `hc connect --session att1` with plain pipes. OBSERVED: works, stdout carries the protocol; when our stdin closes `hc connect` exits 0 (`hc connect exit code 0`); when the core closes it, it exits 0 too. `hc connect` is a dumb byte pump (cli.rs:807-830) that autostarts the core when nobody listens (client.rs:81-96).

**Handshake** (fixtures `attach-wire-minimal.out.bin/.bin`, `.txt`):
```
→ (plain, 75 B)  {"jsonrpc": "2.0", "id": 0, "method": "hello", "params": {"framed": true}}\n
← (plain line)   {"id":0,"jsonrpc":"2.0","result":{"core":{"id":"e9d9…","name":"6a09…"},"features":["framed","attach","events","status","shell"],"framed":true,"generation":1,"methods":[32 names],"version":"0.1.14"}}\n
   ── from the next byte on: frames  [channel u32 LE][kind u8][len u32 LE][payload] (9-byte header, max payload 16 MiB; wire.rs:7-8) ──
→ 00 00 00 00 | 00 | 91 00 00 00   {"jsonrpc":"2.0","id":1,"method":"terminal.attach","params":{"terminal":"wire1","cols":52,"rows":28,"observe":false,"history":0}}
← 00 00 00 00 | 00 | 79 02 00 00   {"id":1,"jsonrpc":"2.0","result":{"channel":1,"terminal":{…633 B Terminal record…}}}
← 01 00 00 00 | 00 | e4 00 00 00   first paint (228 B)
```
The reply on ch 0 always precedes the first-paint frame (control frames are sent before stream frames, wire.rs:233-241; OBSERVED order in every capture). Kinds: 0 DATA, 1 CREDIT (u32 LE bytes consumed), 2 CLOSE, 3 RESIZE (u16 LE cols, u16 LE rows), 4 FOCUS (1/0), 5 FACTS (JSON).

**`terminal.attach` params** (types.rs:352-381, schema/hc.openrpc.json): `terminal` (required: `t7` | name | `machine/t7`), `cols`, `rows` (**required** u16), `observe` (bool, default false), `history` (usize scrollback lines, default 0, "main screen only"), `display` (`Display`, below), `resumed` (bool), `caller` (string; if it is the terminal itself → error `refused`, api.rs:387-396). **Result**: `{"channel": <u32>, "terminal": <full Terminal record>}`. Channel numbers are a per-connection counter starting at 1 (wire.rs:129-131) shared by attach and events streams. Errors (OBSERVED): `not_found` (`no terminal "nope"`), `finished` (`{"hint":"read what it left: hc read t11","kind":"finished"}`, `"message":"t11 has finished"`), `unavailable` (`"t1s is lost, waiting for its new shell"`, hint `retry after the restarted event`), `needs_framed` (SOURCE api.rs:379-385; plain mode).
`Display` = `{fg?: "#rrggbb", bg?: "#rrggbb", cursor?: "#rrggbb", cell?: [w_px, h_px]}` (viewers.rs:17-26). FACTS frame payload = this JSON; sent whenever the viewer's theme/cell size changes; counts as "active" (viewers.rs:213-216). **OBSERVED effect** (`attach-queries-{nofacts,facts}.json`): the core itself answers the program's terminal queries and strips them from the stream, so the viewer's emulator must not answer a second time. A program that sent `OSC 10;? OSC 11;? OSC 12;? CSI 16t CSI 18t CSI c CSI 6n` got, without FACTS: `OSC 10;rgb:ffff/ffff/ffff`, `OSC 11;rgb:2828/2c2c/3434`, `OSC 12;rgb:ffff/ffff/ffff`, `CSI 6;20;10t`, `CSI 8;28;52t`, `CSI ?62;22c`, `CSI 1;1R`; after `FACTS {"fg":"#aabbcc","bg":"#112233","cursor":"#ff0000","cell":[9,18]}`: `rgb:aaaa/bbbb/cccc`, `rgb:1111/2222/3333`, `rgb:ffff/0000/0000`, `CSI 6;18;9t`. (relay.rs strips answered queries; images/APC are the exception.)

**First paint** (OBSERVED bytes; SOURCE viewers.rs:281-290 + vendor screen `paint`): ONE logical blob (queued as one chunk, delivered in ≤16 KiB DATA frames, wire.rs:29) = `ESC[!p` (DECSTR) + mode resets (`?2026l ?9l ?1000l..?1006l ?1015l ?1016l ?2004l ?1l ?66l ?2031l ?2048l`, `ESC[=0;1u`, `?1049l ?1047l ?47l`) + `ESC[H ESC[2J` + [`ESC[?1049h` when the app is on the alt screen] + tab stops (`ESC[3g`, `ESC[9G ESC H` …) + [modes the app had set, e.g. `ESC[?1h ESC[?25l ESC[?66h` for `top`, `ESC[?2004h` for a bracketed-paste app] + history lines (only main screen, `\r\n`-joined) + screen rows + `CUP` + `ESC[0m` + [`ESC]2;<title>ESC\` when a title was set] + `ESC[?9001h|l` + one `ESC]7501;state=…:id=…:title=<b64>:msg=<b64>ESC\` per status record (root first). Examples: `attach-alt-firstpaint.bin` (244 B: `…ESC[?1049l ?1047l ?47l ESC[H ESC[2J ESC[?1049h …tabstops… ESC[Hhello alt ESC[1;10H ESC[0m ESC[?9001l`); `attach-agent-status-title.bin` (450 B, tail `…ESC[21;1H ESC[0m ESC]2;fake agent title ESC\ ESC[?9001l ESC]7501;state=idle:app=fake ESC\`); `attach-scroll-history50.bin` (1496 B = 50 history + 27 screen lines for 200 lines printed; ends `ESC[28;1H ESC[0m ESC[?9001l`). `history` is ignored for alt-screen apps (OBSERVED: `history=0` and `50` both 244 B on an app in alt screen). **No `ESC[3J`/`ESC c` is sent**: it does not clear the viewer's scrollback, so re-attaching into the same emulator instance appends history on top of old scrollback — reset/recreate the emulator per attach.
**The PTY is resized to the new viewer's size BEFORE the first paint** (viewers.rs:75-76) → for a program that does not redraw on SIGWINCH the paint is a reflowed snapshot; for one that does (`top`) a garbled paint is followed within ~5 ms by the app's redraw (`attach-top-resize.json`: frame at t=0.003 shows `.0   0.0   0:00.00 sleep` fragments, next DATA 5 ms later is the full redraw).

**Live output**: raw program bytes as DATA (OBSERVED `attach-agent-live-status.json`: `ESC]7501;state=idle:app=fake ESC\ idle now\r\n` in one frame; OSC 0 title passes through raw). A viewer's emulator must ignore OSC 7501 (it is in the byte stream) — or strip it. Frame boundaries are arbitrary (OBSERVED 4095/13726-byte splits in `attach-nocredit-flood.json`): buffer partial escape sequences / UTF-8 across frames.

**CREDIT** (wire.rs:23-26, 178-251; OBSERVED `attach-nocredit-flood.json`): each stream starts with 256 KiB credit that includes the first paint. Client never sends CREDIT → exactly **262144 bytes in 60 DATA frames, then silence** (flooding terminal). `CREDIT 65536` at t=3.05 → the very next frame is a **full repaint** (`ESC[!p…`, because the backlog passed 4 MiB: `MAX_PENDING`, wire.rs:26,199-207) and exactly 65536 more bytes (327680 total). Control traffic is never blocked: `server.status` on ch 0 answered 1 ms after a 2 s stall. CREDIT must be sent for **event streams too** (same mechanism; `ev_buf` in the probe), and its value = bytes of payload consumed (reference viewer: `payload.len()` after writing it out, attach.rs:241-244).

**CLOSE**: viewer→core: empty CLOSE on the channel; the core answers with an empty CLOSE (OBSERVED `ch=1 CLOSE reason=null`), attach channel is released, PTY size recomputed (viewers.rs:235-250). Core→viewer when the program ends (queued behind unsent output, wire.rs:188-195): reason JSON (OBSERVED):
- exit 3: `{"exit_code":3,"finished_ms":1793307229389,"reason":"exited","signal":null}` (arrived 1.98 s in, `attach-close-exited.json`)
- `hc kill`: `{"exit_code":null,"finished_ms":…,"reason":"killed","signal":1}` (SIGHUP; `attach-close-killed.json`)
- kept terminal, program `kill -9`: `{"exit_code":null,"finished_ms":null,"reason":"signaled","signal":9}` (`attach-kept-lost.json`); attaching during recovery → `unavailable` (above); after `restarted` (≈4 s later) attach works and the first paint is the new shell's.
- core restart/stop/crash: **no CLOSE at all — the byte stream just ends (EOF)**, see §4/§6.
- attach again after finish → error `finished` (above).

**Multi-attach on one connection**: yes (OBSERVED `attach-multichannel.json`: ch 1,2,3 for tick/bytes/alt on one `hc connect`; input to ch 2 echoed on ch 2 only; CLOSE ch 1 and ch 3 independently; `RX bytes per channel {1:515,2:238,3:244}`). Same terminal twice on one connection also gets two channels (counter) [source only].
**`observe`**: OBSERVED `attach-observe.json` (viewer 20x5): DATA `Z` and RESIZE 30x10 are ignored (no hex echo, `hc get` still 200x120); observers are excluded from the size leader and from typing (viewers.rs:187-195, 255). They still receive output and first paint, FOCUS 0 is not forwarded (viewers.rs:224).

**PTY size rules** (SOURCE viewers.rs:252-274; OBSERVED with a program that prints `stty size` on SIGWINCH, `hc get` for the record). Leader = non-observe viewer with the newest `active_at` (attach, DATA, RESIZE, FOCUS 1, FACTS refresh it; `resumed:true` attach starts inactive). No non-observe viewer → "headless" size, default **200x120** (`config.toml` `headless = "COLSxROWS"`, config.rs:18,31-37). Exact timeline (script `sizes.py`, 2 viewers):
| t | event | `hc get` cols×rows | program saw (`stty size`=rows cols) |
|---|---|---|---|
|0.0| nobody attached | 200×120 | — |
|0.7| desktop attaches 120×40 | 120×40 | `SIZE 40 120` |
|1.7| phone attaches 52×28 (newest) | **52×28** | `SIZE 28 52` |
|3.2| phone CLOSEs (desktop still attached, never typed) | **120×40** | `SIZE 40 120` |
|…| desktop CLOSEs too (separate run `sizes2.py`: all viewers gone, t=7.9) | **200×120** | (headless) |
Further OBSERVED (sizes2.py): observer 30×10 attached → unchanged 52×28; phone typed `x` and sent RESIZE 60×30 → 60×30; second desktop viewer 120×40 attaches+types → 120×40; all gone → 200×120. `resumed:true` phone attached while desktop was leader → stayed 120×40; after `FOCUS 1` from phone → 52×28.
**Dead-viewer variant** (ghost.py): `kill -STOP` the phone's `hc connect` (connection open, nothing moves): size stays 52×28 and the core cannot tell; a desktop attaching takes 120×40; when the desktop leaves the size falls back to the ghost's **52×28** and stays so for ≥5 s; `kill -9` of the ghost → 200×120 immediately.

**Alt-screen reconnect** (`attach-alt-firstpaint`, `attach-top-resize`): you get the alt-screen content, not the main screen; a later attach gets exactly the same shape (first paint above), so a viewer that reconnects needs no replay logic.
**Not tested**: `less`/`vi` (not installed in the sandbox); `top` and a hand-drawn alt-screen app were used.

## 2. Keys on a framed attach

**Bytes-in path = raw PTY write.** DATA frames on the attach channel go straight to the PTY master (server.rs:334 → viewers.rs:198-206 `viewer_input` → holder `link.input`). No encoding, no translation, no paste handling. The only transformation: while an agent's `hc send/keys` is injecting, a person's DATA is *held* and delivered afterwards (input.rs:30-52, `Gate::human`). DATA on an `observe` channel is dropped (viewers.rs:190-192). `keys.rs` (name→bytes) is only for `hc keys` / `terminal.keys`, never for viewers.

Reference viewer = `hc attach` (attach.rs:165-337): reads the outer terminal's raw stdin bytes, strips only (a) its detach chord, (b) `ESC[I`/`ESC[O` which it converts to FOCUS frames, (c) its own DA/OSC replies, and forwards everything else as DATA unchanged (attach.rs:294-310). A sequence cut by a read is held up to 50 ms (`incomplete_tail`, attach.rs:59-87, 264) so ESC vs `ESC[A` is judged by timing.

What to send (OBSERVED with a program that prints each byte it reads as hex — `attach-keys-bytes.json` — and with a trap script `attach-signals-via-data.json`):
| key | bytes (DATA payload) | observation |
|---|---|---|
| Enter | `0d` | program read `0d` |
| Esc | `1b` (single write) | read `1b` |
| Up (normal cursor-key mode) | `1b 5b 41` | read `1b 5b 41` (and `1b 4f 41` for `ESC O A` — application mode `?1h` is the viewer's job; `top` sets `?1h`, visible in its first paint) |
| Backspace | `7f` | read `7f` |
| Ctrl+C | `03` | cooked tty: echoed `^C` and the program's `trap INT` ran (`GOT-INT`); raw-mode program read `03` |
| Ctrl+Z | `1a` | `GOT-TSTP` (SIGTSTP) |
| Ctrl+\ | `1c` | **SIGQUIT** (`Quit (core dumped)`, `GOT-QUIT`) — NOT a detach on a framed channel; detach = CLOSE frame |
| Paste | bracketed iff the program enabled `?2004h`: `1b 5b 32 30 30 7e` text `1b 5b 32 30 31 7e` | read verbatim; otherwise raw text. The viewer's emulator tracks `?2004` from the stream (first paint re-sends it). Core's own paste helper strips `ESC[201~` from the text first (input.rs:82-86) — do the same. |
| Focus in/out | **FOCUS frame (kind 4)**, not `ESC[I` | FOCUS 1 → program got `1b 5b 49`, FOCUS 0 → `1b 5b 4f` only because the program had enabled `?1004` (viewers.rs:226-231; OBSERVED `attach-focus.json`). FOCUS 1 also makes this viewer the size leader. |
| Mouse, kitty keyboard (`CSI =…u` / `>…u`) | encoded by the viewer per modes it saw in the stream | core passes bytes through; the first-paint prelude resets `?1000-?1006` and kitty flags (`ESC[=0;1u`) (not tested with a live app) |

**win32-input-mode (`?9001`)**: the core only *reports* it (first paint ends with `ESC[?9001h` or `l`; live `ESC[?9001h/l` pass through; OBSERVED `attach-win32-firstpaint.json` for a program that printed `ESC[?9001h`). It never enables anything on Unix hosts (only ConPTY, i.e. Windows hosts, asks). Reference behavior: `hc attach` **strips every `?9001h/l` from output and keeps sending normal VT bytes** (attach.rs:89-107, test attach.rs:401-402); the desktop app (herdr-app) uses win32 events ONLY for Shift/Ctrl/Alt+Enter when 9001 is on and no kitty flags are active, format `CSI 13;28;<typed>;<down 1|0>;<held>;1_` ×2 (down then up; `typed`=13, 10 with ctrl; `held` = shift 0x10 | ctrl 0x08 | alt 0x02) (herdr-app/src/win32_keys.rs:41-47, terminal.rs:736-738). **Recommendation for Waycar on macOS/Linux hosts: ignore 9001 (strip it from what the emulator sees) and send plain VT bytes.**

## 3. `hc attach T` on a real pty

Harness: python `pty.openpty()` + `TIOCSWINSZ`, child in its own session (`ptyattach.py`, `two.py`).
- **Works** over a pty: `hc attach tty1` (52x28, TERM=xterm-256color) → program output, Ctrl+\ (byte `1c`) → exit code 0 and stderr text `[detached from tty1]` (cli.rs:346-349 prints with `eprintln!`). Works for TERM=`dumb`, `vt100`, `linux` too (no TERM check). Ctrl+\ is the default `detach_key` (`ctrl+\`); change in the **host's** `~/.config/herdr-core/config.toml`: `detach_key = "ctrl+]"` (any `ctrl+<letter|@[\]^_>`, config.rs:9,68-81). Recognized as raw `1c`, kitty `CSI 92;5u`, or modifyOtherKeys `CSI 27;5;92~` (attach.rs:30-53). A phone can send `1c` trivially; but the closing the SSH channel detaches just as well (below).
- **Startup handshake with the outer terminal**: hc writes `OSC 10;? OSC 11;? OSC 12;? CSI 16t CSI c` then `ESC[?1004h` and waits ≤500 ms for the DA1 reply to learn colors/cell size (attach.rs:17,176-191). OBSERVED first paint at 0.004 s when the terminal answers DA1, **0.506 s when it never does**. After attach it also asks again on focus-in.
- **Options**: `--history N` OBSERVED (pty, 200-line terminal at 52x28): `--history 0` → 27 `scrollline`s in 1007 B, `--history 60` → 87 lines in 2006 B. `--observe`: OBSERVED typed `Q` never reached the program (`51` hex absent) and the size stayed 200x120; without `--observe` it did. Ctrl+\ still detaches an observer. **No pty and no `--observe` → refused**: `{"error":{"hint":"use --observe to watch from a pipe","kind":"usage","message":"attach needs a terminal"}}`, exit 2. A piped `--observe` streams raw output and ends when its stdin ends (`[detached from tty1]`).
- **Resize**: `TIOCSWINSZ` on the pty → SIGWINCH → hc polls `window_size()` every ≤100 ms and sends RESIZE (attach.rs:316-322). OBSERVED: program saw `SIZE 24 80` → `SIZE 28 52` → `SIZE 30 100` for 80x24 → 52x28 → 100x30.
- **Exit / messages** (stderr, exit code **0** in all of these): program exited: `[exiter2 finished: exited]`; killed: `[killme2 finished: killed]`; Ctrl+\: `[detached from T]`; core lost: `[lost the core; it keeps T running: hc attach T]` (attach.rs:331-336). Errors: unknown terminal exit 3 (`error: no terminal "nope"` + `hint:`), finished exit **11** (`error: t1f has finished`, hint `read what it left: hc read t1f`); exit-code table rpc.rs:55-70 (usage 2, not_found 3, machine_unknown 4, unavailable 5, invalid_params 6, config 8, blocked 9, status_mismatch 10, finished 11, other 1). The program's own exit code is NOT propagated.
- **Pty closed / signals** (OBSERVED, `hc get` size afterwards): pty master closed (= SSH channel closed) → hc exits at once, viewer removed, size 52x28 → **200x120** within 10 ms; SIGTERM → exit 0; SIGKILL → exit -9, core still sees EOF and drops the viewer immediately. (exit 101 + a panic appears if stderr is the closed pty itself; irrelevant.)
- **Env needed**: hc finds its core by `HC_SESSION`, `XDG_RUNTIME_DIR`, `HOME` (or `HC_SOCKET`) — paths.rs:17-49, platform/unix.rs:88-95. OBSERVED with `env -i PATH HOME`: `hc ls` reached **a different, freshly auto-started core** (state `$HOME/.local/state/herdr-core/default/`, `hc: no systemd user manager here: the core ends with whatever started it` on stderr; it kept running after the command exited); with `XDG_RUNTIME_DIR`+`HC_SESSION` set it reached the right one. With no `XDG_RUNTIME_DIR` the client uses `/run/user/<uid>/herdr-core/` if that directory exists, else `$XDG_STATE_HOME|~/.local/state /herdr-core/<session>/<session>.sock` (docs/security.md:70-72) — so an ssh login without XDG_RUNTIME_DIR still finds a core that a Linux user service started (same uid dir); `hc connect --session NAME` replaces `HC_SESSION=NAME` (cli.rs `--session`). A running core with a different socket than this env computes is detected through `core.lock` and refused (client.rs:90-92,103-114: "the core listens at X, but this shell looks at Y").
- **Two `hc attach` at once** (OBSERVED, `two.py`; same size rules as §1): A 80x24, then B 52x28 → 52x28; A types → 80x24; B pty resized 60x30 → 60x30; B detaches → 80x24; A detaches → 200x120. Both viewers receive all output and both can type (interleaved bytes `41 61 42 62` arrived in order at the program and were echoed to both). Each viewer draws what the core paints for the *leader's* geometry (cursor `ESC[24;39H` for A vs `ESC[25;39H` for B).

**Versus Waycar's current `herdr agent attach` (AGENTS.md:83-89,116)**: herdr TUI attach needs a TTY (ratatui), attaches by agent or `terminal attach <id> [--takeover]`, **owns the pane size until it exits** with a resize lock and **no heartbeat** — an orphaned attach pins the size (AGENTS.md:116). hc: (+) no TTY or ratatui — with framed `hc connect` the app is the terminal emulator, no extra TUI layer, no takeover concept (many typing viewers, newest-active wins); (+) the size is leader-based, so a ghost viewer never pins it while another viewer is active; (+) first paint/reconnect = one repaint, optional history; (+) one connection can carry control (list, events, send) and many attaches; (−) no heartbeat on attach streams either — a half-open SSH leaves a ghost viewer (it still counts for sizing when nobody else is attached); (−) detaching the last typing viewer snaps the PTY to 200x120 (SIGWINCH to the agent each time; set `headless` in the host config if that churn matters); (−) the viewer must implement CREDIT/FACTS/FOCUS/key encoding itself (the pty `hc attach` path hides all of it but costs a pty, TERM negotiation, a 500 ms DA1 wait and the Ctrl+\ chord).

## 4. `events.subscribe`

**Params** (types.rs:391-404): `terminal` (one address), `children_of` (parent address), `labels` (map; terminal must carry ALL). Unknown terminal → error `not_found` immediately (OBSERVED plain: `{"error":{"code":-32000,"data":{"hint":"see \`hc ls --all\`","kind":"not_found"},"message":"no terminal \"nosuch\""},"id":7,…}`). Unfiltered subscribers also get `doc` events; filtered ones never do (schema/README.md:165-174).
**Result**: `{"seq": N, "terminals": [Terminal…], "channel": <u32>|null}` — OBSERVED framed `{"channel":1,"seq":170,"terminals":[26 records]}`, plain `{"channel":null,"seq":196,"terminals":[]}`. Snapshot is terminals only (no docs).
**Framed**: events arrive as JSON-RPC notification **lines** (`…\n`) inside DATA frames on the returned channel, with the same 256 KiB credit (send CREDIT!) and lines may be split across frames (data_lines, wire.rs:212-221). **Plain** (no `hello framed`, `hc events` uses this): after the reply the connection carries only notification lines; **further requests on it get no reply** (OBSERVED: a second request produced no line; server.rs:166-169,222-253 reads and ignores). Plain subscriber slower than 1024 queued events gets `missed`; stuck 30 s → dropped (server.rs:224,248-251; events.rs:13).
**Every event captured** (`attach-events-framed.json`, one run; the program is a `sh` script printing OSC 0 + OSC 7501; seq values in that run):

Event envelope: `{"jsonrpc":"2.0","method":"event","params":{"data":{…},"seq":N,"terminal":"t1k","type":"…"}}` (key order alphabetical). Label filter (`attach-events-label-filter.json`, filter `{"grp":"a"}`): `hc label grp=a` → `labels` event with `data:{labels, record:<whole Terminal>}` (newly matches); `grp=b` → `labels` event without `record` (leaves your view, you still get it); `other=1` afterwards → nothing. Terminals on machines this core added appear in the same stream as `machine/t7` (schema/README.md:112-116; not tested).
**Heartbeat**: `{"jsonrpc":"2.0","method":"heartbeat","params":{"seq":N}}` — OBSERVED at exactly **15.00 s and 30.00 s** after subscribe in framed mode (`attach-events-framed.json`: t=15.004, t=30.005, each only when nothing is queued, in plain mode t=15.00 `attach-events-plain.txt`); fixed timer from subscription, not reset by events (server.rs:216-219, 256-275). `HC_HEARTBEAT_MS` env on the core overrides it (tests).
**`missed`** (OBSERVED, `attach-events-missed.json`): subscriber that stops sending CREDIT while a terminal produced ~80k status events: events up to seq 44052 delivered (256 KiB), the rest dropped, then `{"jsonrpc":"2.0","method":"missed","params":{"seq":71210,"terminals":[30 records]}}`, then events resume at seq 71211. Apply: replace local state with `terminals`, ignore events with `seq ≤ params.seq`. A backlog line is truncated to its own newline so the stream stays line-aligned.
**`seq` and restarts** (OBSERVED): `seq` counts per core *process*: 84512 in the old core, **15** in the snapshot after two core restarts; core id (`hello.core.id`) is stable across restarts (core.json) so it cannot be used to detect one — compare `server.status.pid`/`uptime_ms`, or just always re-snapshot.
**What a long-lived `hc connect` sees when the core restarts** (OBSERVED `attach-core-restart.json`: attach + events on one connection, `hc server restart` at t≈2.0): frames continue until t=1.43, then **EOF on stdout at 1.997 s, `hc connect` exit code 0, no CLOSE/goodbye frame**; `hc server restart` took 3.09 s; new core pid, same holder pid, same program pid, and `tick` output kept flowing in the gap. `hc update`/`hc update --from` do the same (they call `server.restart`, cli/update.rs:60-82). `kill -9` of the core: same EOF; the socket file stays (stale), the next `hc connect`/`hc get` autostarted a core in 25 ms and adopted the live terminals (13 live, same pids). So: **the connection dies, terminals survive**.
**Dead viewer / dead SSH**: the core only learns from EOF/IO error on the socket (server.rs:181-189; no keepalive, no timeouts for framed viewers; OBSERVED a SIGSTOPped `hc connect` stayed a viewer for the ≥5 s watched and kept size leadership fallback, §1). An SSH exec channel that closes properly → sshd closes `hc connect`'s stdin → it exits 0 (OBSERVED) → core detaches instantly (OBSERVED 10 ms for pty close, `kill -9` of hc). A half-open TCP connection is only noticed when sshd notices: hc's own machine links use `-T BatchMode=yes ConnectTimeout=10 ServerAliveInterval=15 ServerAliveCountMax=4` (machines.rs:219) — copy those. App-level liveness probe [INFERENCE]: `server.status` on ch 0 answers instantly even while a stream is credit-stalled (OBSERVED 1 ms), and events heartbeats arrive every 15 s on the events channel.
**Recovery rules after reconnect** (derived): (1) new `hc connect` + `hello`, (2) `events.subscribe` → replace ALL local terminal state with the snapshot (never merge across connections; `seq` restarts), (3) `doc.get` for every watched document *after* subscribing (snapshots hold no docs; schema/README.md:176-182), (4) re-`terminal.attach` each open terminal (full repaint, `history` as needed; `resumed:true` if the user has not interacted yet), (5) on `lost` expect attach CLOSE and wait `restarted`; on `finished` read with `hc read`/`terminal.read`.

## 6. Lifecycle (OBSERVED; session att1/att2)

- **Program exits**: `finished {exit_code, finished_ms, reason:"exited", signal:null}` (exit 7 → `exit_code 7`).
- **`hc kill`** → program gets SIGHUP: `finished` `reason:"killed"`, `signal:1`, `exit_code:null`; then `hc rm` → `removed {}` (rm of a live terminal is refused: kind `live`, hint `kill it first`, api.rs:288-297). Finished terminals stay readable until `rm` (cap 500).
- **Non-kept program killed by signal** (`kill -9`): `finished`, `reason:"exited"`, `exit_code:null`, `signal:9` (`hc get`).
- **Kept** (`hc run --keep` / `hc keep T`): `kill -9` → `status` null, `lost {reason:"signaled",signal:9}` (state stays `live`, pid null), attach CLOSE with that reason, attach/send → `unavailable "…lost, waiting for its new shell"`; after **2.3 s** `restarted` (whole record, argv `["/bin/sh"]`, new pid, same address/name; the original command is never re-run). `hc keep --off` → `keep {false}`. Backoff after repeated failures 1.5, 3, 6, 12, 30, 60 s (schema/README.md:127-130; holder.rs:379-381).
- **Holder killed (`kill -9` of `herdr-core hold`)**: non-kept → `finished reason:"holder_lost"`; kept → `lost reason:"holder_lost"`, state live, restarted later than for a signal death: still `reason:"holder_lost"`, pid null 6 s after the kill, a new shell by ≈11 s.
- **`hc server restart`** (and `hc update`): programs and holder survive (same pids, proof: `kill -0 $PID`; `uptime_ms` of new core 45), core pid changes, **all client connections EOF** (§4); command took 3.09 s. Source: `server.restart` = "screens are saved, programs keep running, the next core adopts them".
- **`hc server stop`**: **programs die** (pids checked dead): non-kept → `finished reason:"server_stop"` (seen at next start); kept → `live` with `reason:"stopped_by_restart"` until the next core start gives it a fresh shell (observed shell pid after 3 s: `argv ["/bin/sh"]`, `reason:null`). Do not use stop as "restart".
- **Core `kill -9`**: terminals survive in the holder; stale socket file remains (`test -S` still true); next client autostarts a core and adopts them.
- **Core autostart when nothing listens**: every client call except `hc server stop` and `hc update` start one (`connect_or_start`, client.rs:73-96): `hc ls`, `hc get`, `hc events`, `hc attach`, `hc connect`, `hc server status`. On Linux with a systemd user manager (`/run/user/<uid>/systemd/private`) the core/holder are `systemd-run --user` services (platform/systemd.rs:52-118) [not testable here: the sandbox has no user manager; custom `XDG_RUNTIME_DIR` also bypasses it]; otherwise `setsid` detached children (platform/unix.rs:122-135) — OBSERVED they survive the starter.

## Gotchas for the Swift engineer

1. **Every `hc` subcommand except `-V/--version`, `server stop` and `update --from` autostarts a core** — including `hc connect`, `hc server status`, `hc ls`. Probe with `--version` and `test -S`/`core.lock`, never with `server status`.
2. Use `herdr-core`, not `hc`: the installer creates the `hc` symlink only if no `hc` exists on PATH/in `~/.local/bin`, and a foreign `hc` may be first on PATH. Verify `--version` prints `hc <digits>`.
3. The exec command must be `sh -c '… exec "$p" connect'` with `-T`/no pty and ServerAlive options; anything the login shell prints to stdout corrupts the stream (first byte after the hello line is a frame header). Pin the session with `--session NAME` or `HC_SESSION=NAME`; without matching `XDG_RUNTIME_DIR`/HOME the command silently starts and uses a *different* core.
4. Send **CREDIT** for attach AND event channels or the stream stops dead after exactly 262144 bytes; an unread stream for >4 MiB gets a full repaint (`ESC[!p…`) mid-stream, not a backlog — the emulator must treat `ESC[!p` + `ESC[2J` as "start over".
5. First paint does not clear scrollback (no `ESC[3J`) and is preceded by DECSTR; re-create or reset the emulator on every attach, otherwise history lines duplicate. The OSC 7501 status sequences and OSC titles are in the byte stream; the emulator must swallow OSC 7501.
6. Frame payload boundaries are arbitrary: split escape sequences, UTF-8 and (for events) JSON lines across frames; the ch-0 reply to `terminal.attach` always arrives before the first paint.
7. Attach resizes the PTY **before** the first paint, so the first paint of a non-redrawing app is a reflowed snapshot; full-screen apps redraw ~5 ms later (SIGWINCH). Send the real `cols`/`rows` in the attach params (both required).
8. Size = newest *active* non-observe viewer. Detach/CLOSE of the last one snaps the PTY to 200x120 (config `headless`). A phone that only wants to watch should attach `observe:true`; one returning after a dropped link should use `resumed:true` until the user types/resizes/focuses.
9. Key bytes are the viewer's job: Enter `\r`, Esc `\x1b` alone, arrows `ESC[A..D` or `ESC O A..D` per DECCKM, Ctrl+C `\x03` (really SIGINT), **Ctrl+\ `\x1c` is SIGQUIT on a framed attach** (detach is a CLOSE frame), paste bracketed only when the stream set `?2004h` (strip `ESC[201~` from the text). Send focus as FOCUS frames, not `ESC[I`.
10. Ignore `?9001` on Unix hosts; the reference viewer strips it and sends plain VT. Only a Windows (ConPTY) host cares.
11. The core answers the program's color/size/DA/CPR queries itself (and strips them); do not let the emulator answer them again, and send FACTS (`fg`,`bg`,`cursor`,`cell`) so answers match the phone theme.
12. Core restart/update/crash = **EOF with no CLOSE frame**, `hc connect` exit 0; terminals survive (`server restart`, core crash) — **but `server stop` kills programs**. `seq` restarts at each core process; on reconnect always re-snapshot (`events.subscribe`), re-`doc.get`, re-attach.
13. No keepalive in the protocol: a half-open SSH keeps a ghost viewer (it counts for sizing when alone). Use SSH keepalives (hc uses 15 s × 4); the only core-originated liveness frame is the 15.00 s `heartbeat` on the *events* channel.
14. Terminal ids are opaque strings (`t1`…`t9`, `t1a`…, `t1k`, `t1y`); `kill` is SIGHUP (`signal:1`, reason `killed`), non-kept `kill -9` is `reason:"exited"` with `signal:9`; kept terminals `lost`→`restarted` in ~2.3 s (holder loss: a new shell by ≈11 s) and attach returns `unavailable` meanwhile.
15. Programs inherit the **core's** env (not the client's), minus `SSH_*`; they get `HC_TERMINAL_ID`/`HC_TERMINAL_SOCKET`/`HC_SESSION`, never `HERDR_*` — but a core started inside a herdr TUI pane would leak that pane's `HERDR_*` into every hc terminal.
