## Probe answers

1. **Hook config and events**
   - **Files (docs).** `~/.gemini/config/hooks.json` (global), `<workspace>/.agents/hooks.json`, a `hooks` key in `~/.gemini/antigravity-cli/settings.json`, and plugin `hooks.json`. The global file is agy-only (Gemini CLI reads `~/.gemini/settings.json`, not `~/.gemini/config/`).
   - **Schema (docs, live).** A map of named groups → events: `{"<group>": {"enabled"?: bool, "PreToolUse": [{"matcher": "<regex>|*", "hooks": [{"type": "command", "command": "…", "timeout": 30}]}], "PostToolUse": [same], "PreInvocation": [{"type": "command", "command": "…"}], "PostInvocation": [same], "Stop": [same]}}`. Tool events nest `matcher`/`hooks`; the other three list handlers directly. herdr's integration merges its own `"herdr"` group beside others and removes only that group on uninstall (live), so Waycar can own a `"waycar"` group the same way.
   - **Events:** `PreToolUse`, `PostToolUse`, `PreInvocation` (before each model call), `PostInvocation`, `Stop`. There is **no SessionStart, SessionEnd, UserPromptSubmit, Notification or permission event** (docs, live).
   - **Live sequences.**
     - Plain turn: `PreInvocation` (invocationNum 0) at submit → `PostInvocation` → `Stop` (`fullyIdle: true`, `terminationReason: "NO_TOOL_CALL"`) ~1.5 s later.
     - Tool turn with approval: `PreInvocation` → `PreToolUse` (`toolCall.name: "run_command"`) **just before** the approval dialog draws → nothing while the dialog is up → after approval `PostToolUse` → `PostInvocation` (invocation 0 ends only after its tools) → `PreInvocation` (1) → `PostInvocation` → `Stop`.
     - **Denied tool: `PreToolUse`, then nothing** — no `PostToolUse`, `PostInvocation` or `Stop` (live, conversation `898d0986…`).
     - **Esc during a turn: `PreInvocation`, then nothing** (live).
     - Exit (Ctrl+D twice): nothing.
     - `PreToolUse` fires for every tool, auto-allowed or not, so it cannot signal "blocked".
   - **Payload (live).** Every event: `conversationId`, `transcriptPath`, `artifactDirectoryPath`, `modelName` (e.g. `gemini-3.1-pro-low`), `workspacePaths`. Plus `invocationNum`/`initialNumSteps` (invocations), `stepIdx`/`toolCall{name,args}` (tools; `PostToolUse` adds `error`), `executionNum`/`terminationReason`/`error`/`fullyIdle` (Stop). **`transcriptPath` is `…/brain/<id>/.system_generated/logs/transcript_full.jsonl`**; the docs say `transcript.jsonl`.
   - **Hook environment (live).** `ANTIGRAVITY_CONVERSATION_ID=<conversationId>` on every hook. The hook's working directory is the **directory of the hooks.json** (`PWD=/home/waycar/.gemini/config`), not the session cwd: commands need absolute paths.
   - **Output.** `PreToolUse` documents a required `decision`, but empty stdout kept the normal approval flow (live). Printing `{}` (herdr does) is the safe no-op.
   - **Reload (live).** hooks.json is re-read per turn: herdr's integration installed mid-session reported on the next prompt.
2. **tmux pane identity (live).** Hooks run as `sh -c '<command>'`, a child of the pane's `agy`; `$TMUX_PANE` is inherited and correct; `ps -o tty= -p $PPID` (the `sh`) gives the pane tty (`pts/0` = `#{pane_tty}`), so `waycar-hook`'s tty guard accepts agy hooks as they are. In a herdr pane: `HERDR_ENV=1`, `HERDR_PANE_ID`, `HERDR_SOCKET_PATH`, no `TMUX`.
   - **No Claude-hook bleed (live).** With Waycar's claude Status Hooks installed, an agy turn in tmux left `@waycar_agent`/`@waycar_status`/`@waycar_session` unset.
3. **Executable (live).** `agy` (`~/.local/bin/agy`, 204 MB Go binary), equal to the Waycar raw value `agy`. herdr kind `agy` (aliases `antigravity`, `antigravity-cli`).
4. **Transcript (live)**
   - **Files.** `~/.gemini/antigravity-cli/brain/<conversationId>/.system_generated/logs/transcript_full.jsonl` and `transcript.jsonl` (also `chunks/transcript*/00000000.jsonl`). The two differ only in `tool_calls[].args`: `transcript.jsonl` stores each arg JSON-encoded as a string (`"CommandLine":"\"echo …\""`), `_full` stores typed values. Use `_full` (the hook's path). Also `conversations/<id>.db` (SQLite) and `brain/<id>/.user_uploaded/` (attachments).
   - **Records.** Flat JSONL, one step per line, no parent tree: `{step_index, source: USER_EXPLICIT|MODEL|SYSTEM, type: USER_INPUT|PLANNER_RESPONSE|GENERIC|SYSTEM_MESSAGE, status: DONE|ERROR, created_at (ISO, second precision), content, tool_calls?: [{name, args}], error?, media?: [{mime_type, uri}], input_tokens?, output_tokens?}`.
   - **User text** is wrapped: `<USER_REQUEST>\n…\n</USER_REQUEST>\n<ADDITIONAL_METADATA>…</ADDITIONAL_METADATA>` (first turn adds `<USER_SETTINGS_CHANGE>`). Assistant text is `PLANNER_RESPONSE.content`; a tool call is a `PLANNER_RESPONSE` with `tool_calls`, its result a `GENERIC` step (`Created At: …\nCompleted At: …\n\nThe command exited with code 0.\nOutput:\n…`).
   - **During an approval** the transcript already holds the tool-call step; the result step appears only after approval. A denial is a `GENERIC` step with `status: "ERROR"` and `error: "permission check failed for command …"`.
   - **Resume** appends to the same file and inserts a `SYSTEM_MESSAGE` step ("All your subagents and background tasks have been stopped due to server restart…") after the next user step. The model gets that notice as its own user message after the prompt (`The following is a <SYSTEM_MESSAGE> not actually sent by the user. … <SYSTEM_MESSAGE>…</SYSTEM_MESSAGE>`): the lab mock, which echoes the last user message, answered the first resumed prompt with the notice's last word (`waycar-mock-reply: a`, transcript step 10 of `8e00464e…`, and the harness lab e2e run of 2026-10-12), so a request's last user text is not always the prompt.

## Recommended implementation per layer

- **tmux Status Hooks.** Add `agy` to `HOOK_AGENTS`; JSON-merge a `"waycar"` group into `~/.gemini/config/hooks.json` (detect via `~/.gemini/antigravity-cli` or `agy` on PATH). Absolute command paths (hook cwd is the config dir); print `{}`.
  - `PreInvocation` → `working` + session report; `Stop` with `fullyIdle: true` → `done` (false → stay `working`).
  - **Blocked has no hook**, and **deny/Esc fire nothing**, so hooks alone leave the pane stuck on `working`. A tmux screen fallback is required: blocked when the bottom two non-empty lines contain `navigate` and `tab amend` (or `esc skip`); idle when the footer reads `? for shortcuts` with no spinner. Port herdr's `agy.toml` rules.
  - **Host-side Blocked (implemented, live 2026-10-12).** The app's screen read covers display only while it is connected, and pushes come only from statuses hooks write, so `PreToolUse` (`{"matcher": "*", "hooks": [...]}`) runs `waycar-hook agy watch-approval`, which starts `waycar watch-approval` detached (plugin `src/approval-watch.js`): it reads the visible pane every 250 ms for 5 s, writes `blocked` once the permission rule matches, then `working` once the dialog is gone. Live in the lab (tmux 3.4, `@waycar_status` sampled every 0.25 s): agy ran the nested `PreToolUse` handler; `blocked` came 6.1 s after `working`, the mock's 6 s opening turn plus at most a poll; Enter (approve) gave `working` within 0.5 s, then `done` from `Stop`, and the watch exited.
  - **One watch per pane (live 2026-10-12, tmux 3.4).** The watch holds `@waycar_approval_watch` while it runs; each `PreToolUse` sets `@waycar_approval_poke` and reads that token in one tmux call, starting a watch only when no live `watch-approval` holds it, and the watch's writes are compare-and-set (`if-shell -F` on the seq). Eight `watch-approval` hooks fired at once from the pane left one watch process; it wrote `blocked` for a drawn dialog, `working` once it cleared, and unset its token. A real agy `WAYCAR_TOOL` turn: one watch, `blocked` at 6.25 s, Enter → `working`, the watch gone and its token unset, then `done`.
  - Tty guard works unchanged (`$PPID` is the `sh` on the pane tty).
- **hook-session (agy).** Session id from `conversationId` (or `ANTIGRAVITY_CONVERSATION_ID`), transcript from `transcriptPath`. First available at the first `PreInvocation`; there is no launch-time event.
- **Notifications.** `done` from `Stop`; `blocked` on tmux from the Host's approval watch (above), on herdr from herdr's screen detection.
- **Chat Mode.** Prompt route: new `agyAddDir` route — stage `<dir>/AGENTS.md` and pass `--add-dir <dir>` (keep the file until the Agent closes; re-pass on resume). First message `-i <text>`. Model/effort: `--model <family> --effort <level>`, `--effort` alone, or a combined id alone; never a combined id plus `--effort` (silent fallback interactively).
- **Transcript.** New parser for `transcript_full.jsonl`: user = `USER_INPUT` content minus the `<USER_REQUEST>` wrapper and metadata; assistant = `PLANNER_RESPONSE.content`; activity = `tool_calls` / `GENERIC`; `status: ERROR` → error line; timestamps from `created_at`; skip `SYSTEM_MESSAGE`.
- **Images.** Read: `media[].uri` from the transcript. Send: **cannot support** over SSH/tmux — the only attach path is the local clipboard, and agy disables it under SSH.
- **Resume / Closed Sessions.** Keep `--conversation <id>` (live). No-id fallback could be `-c` (most recent; scope not verified), else `[]`.
- **Message jump.** Default inline, no mouse → standard path.
- **Skills.** Catalog matches the docs; verify the flat-`.md` form before relying on it.
- **Prompt gate.** Generic `launch_pending` gate is enough (box within 0.7 s).
- **tmux launch.** `executable = "agy"`; no `--no-daemon` equivalent.
- **Agent Summaries.** `agy -p "<instruction>"` works headless (live, text output); `--output-format json` exists (help).
