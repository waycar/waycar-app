## Which mode to launch

`hermes` (= `hermes chat`) starts the **classic prompt_toolkit REPL**, inline, unless `display.interface: tui` is set; `--tui` starts the Ink TUI (node + a Python `tui_gateway`), alt screen + mouse; `--cli` forces the REPL (help, live). herdr's `agent start --kind hermes` runs bare `hermes` (live: argv `["hermes"]`), and its manifest detects both UIs. **Waycar should launch the classic REPL** (no `--tui`): native scrollback, no mouse capture, and the same hooks fire.

## Probe answers

1. **Hook config and events**
   - **Shell hooks (docs, live):** `hooks:` in `~/.hermes/config.yaml`, `{<event>: [{command, matcher? (tool events), timeout? (60, max 300), fail_closed? (pre_tool_call)}]}`. `command` is `shlex.split` and executed without a shell (quote JSON args with single quotes). Python plugins (`~/.hermes/plugins/<name>/` + `plugins.enabled`) are the other mechanism (herdr's integration uses it).
   - **Consent (live).** Each new `(event, command)` pair blocks startup with `⚠ Hermes is about to register a shell hook that will run a command on your behalf. … Allow this hook to run? [y/N]:`. Bypass: `--accept-hooks`, `HERMES_ACCEPT_HOOKS=1`, `hooks_auto_accept: true`, or an entry in `~/.hermes/shell-hooks-allowlist.json` (`{"approvals": [{"event", "command", …}]}`, exact command string). `--accept-hooks` wrote the entries there (live). Non-TTY runs skip unapproved hooks silently (docs).
   - **Events used (live):** `on_session_start` (first turn of a new session, **not** at launch), `pre_llm_call` (each turn), `pre_tool_call`, `post_tool_call`, `pre_approval_request`, `on_human_input_request` (`kind: approval|clarify|sudo`), `on_human_input_resolved` (`outcome`), `post_approval_response` (`choice`), `post_llm_call` (successful turn), `on_session_end` (**every turn end**, incl. interrupts), `on_session_finalize` (exit, `reason: "shutdown"`). Also available: `on_session_reset`, `agent_loop_stopped`, `subagent_start/stop`, stream/API observers (source `hermes_cli/plugins.py`).
   - **Live sequences (REPL).**
     - Turn 1: `on_session_start` → `pre_llm_call` (`is_first_turn: true`) → `post_llm_call` → `on_session_end {completed: true, interrupted: false, turn_exit_reason: "text_response(finish_reason=stop)"}`.
     - Approval: `pre_llm_call` → `pre_tool_call {tool_name: "terminal", tool_input: {command}}` → `pre_approval_request` → `on_human_input_request {kind: "approval", request_id, prompt}` → dialog → `on_human_input_resolved {outcome: "once"}` → `post_approval_response {choice: "once"}` → `post_tool_call {status: "ok", duration_ms}` → `post_llm_call` → `on_session_end`. In the TUI `on_human_input_request` came before `pre_approval_request`.
     - Ctrl+C mid-turn: `pre_llm_call` → `on_session_end {completed: false, interrupted: true, turn_exit_reason: "interrupted_during_api_call"}`; no `post_llm_call`.
     - `/exit`: `on_session_finalize {reason: "shutdown"}`.
   - **`echo` is not dangerous**, so the mock's tool call ran without approval by default. To force the dialog the probe used a `pre_tool_call` hook printing `{"action":"approve","message":"waycar-probe-approval"}` (escalate to the human gate, docs).
   - **Payload (live):** `{hook_event_name, tool_name, tool_input, session_id, cwd, profile, extra: {…event kwargs, telemetry_schema_version: "hermes.observer.v1"}}`. `session_id` format `YYYYMMDD_HHMMSS_<6 hex>`. No transcript path (there is no transcript file).
   - **Hook env (live):** `HERMES_SESSION_ID`, `HERMES_HOME`, `HERMES_INTERACTIVE=1`, `HERMES_AGENT=true`; cwd = session cwd.
2. **tmux pane identity (live).** `$TMUX_PANE` preserved. REPL: the hook's `$PPID` is the hermes Python process, on the pane tty. TUI: `$PPID` is `python3 -m tui_gateway.entry` (child of `node`, child of `hermes`), also on the pane tty. The tty guard holds in both. **No Claude-hook bleed**: a hermes turn with Waycar's claude hooks installed left the `@waycar_*` options unset (live); hermes has no claude-settings loader (source).
3. **Executable (live).** `hermes` (`~/.local/bin/hermes`, an sh wrapper that execs `~/.hermes/hermes-agent/.hermes/bin/hermes` → bundled `python3 -I -c …`); ps comm `hermes`. Equals the kind id.
4. **Transcript (live).** No transcript file (`~/.hermes/sessions/` stays empty). Sessions live in SQLite `~/.hermes/state.db` (WAL). Substitute: **`hermes sessions export --format jsonl --session-id <id> <file|->`** (0.67 s): one JSON object per session with metadata (`id`, `cwd`, `model`, `title`, `message_count`, …) and `messages[]` of `{role: user|assistant|tool, content, tool_calls (OpenAI shape), timestamp (epoch float)}`. An interrupted turn is stored as assistant text `Your request was not processed. Send it again if you still want me to carry it out.` A failed-vision image turn stores the placeholder text in the user content. Also `md`, `html`, `trace` formats.
5. **Chat Prompt route (live).** **`HERMES_EPHEMERAL_SYSTEM_PROMPT=<text>`** is appended to the end of the system prompt (`…<!-- End Hermes runtime environment -->\n\nWAYCAR_SYSPROMPT_MARKER_HERMES_ENV`). It is applied at API time and not persisted, so a resume needs it again (source `agent/conversation_loop.py`, `hermes_cli/cli_init_mixin.py:255`). There is no flag; herdr's `agent.start` passes args only, so the env must come from the pane (`tab.create {env}` / `new-window -e`). Persistent alternatives: `agent.system_prompt` in config.yaml, `--skills <name>` (preloaded skill text), `AGENTS.md` in the cwd (help/source).
6. **First message (live).** `hermes chat -q "<text>"`: on a TTY it is submitted as the first turn and the REPL stays open.
7. **Resume (live).** `hermes --resume <session_id>` reopened the session twice (history panel `↻ Resumed session …`). Exit prints `Resume this session with:` / `hermes --resume <id>` / `hermes -c "<title>"`. Resuming `cd`s into the recorded cwd unless `--no-restore-cwd`. `ClosedSession` `.hermes → ["--resume", id]` is correct.
   - **Session-less resume (source + live, 2026-10-12).** Bare `--continue` first follows this terminal's breadcrumb, `~/.hermes/terminal-sessions/<terminal id>` (the tty path, e.g. `tty-dev-pts-2`, else `TMUX_PANE`; `hermes_cli/terminal_breadcrumbs.py`, gated by `session.terminal_continue`, default on), and only without one takes the most recent session. A new pane that reuses a `/dev/pts/N` therefore reopens whatever session last ran on that tty: in the harness lab e2e (hermes on herdr) `--continue` reopened an unrelated earlier session. `--resume latest` skips the breadcrumb and resolves the most recent session of the workspace (git root, else cwd), falling back to the global most recent (`hermes_cli/main.py` `_resolve_chat_session_args`, `_resolve_last_session`). `ClosedSession` uses `["--resume", "latest"]` without an id.
8. **Model and effort (live, mock log).** `hermes chat -m waycar-model-flag --reasoning high` sent `"model": "waycar-model-flag"` and `reasoning_effort: "high"`. Levels: `none, minimal, low, medium, high, xhigh, max, ultra`. Default sends `medium`. Top-level `hermes -m` is documented for `-z`/`--tui` only; `hermes chat -m` works in the REPL.
9. **Skills (source, live listing).** `~/.hermes/skills/<category>/<name>/SKILL.md` (54 bundled, one category level). Project `<root>/.hermes/skills` and `<root>/.agents/skills` load **only if the root is in `skills.trusted_project_dirs`** (`agent/skill_utils.py`). Also `skills.external_dirs`. Precedence: project > local > create_dir > external. Invocation `/<skill-name>` (catalog; not exercised).

## Recommended implementation per layer

- **tmux Status Hooks.** Add `hermes` to `HOOK_AGENTS`; write a `hooks:` block in `~/.hermes/config.yaml` **and** matching entries in `~/.hermes/shell-hooks-allowlist.json` (otherwise every launch stops on the consent prompt). Mapping: `pre_llm_call` → `working`; `on_human_input_request` → `blocked`; `on_human_input_resolved` → `working`; `on_session_end` → `done` (`interrupted: true` → `idle`); `on_session_finalize` → `release`. Tty guard works unchanged. Prefer a JSON-aware entry (node) for `on_session_end`. Editing YAML safely is the cost; a Python plugin (like herdr's) is the alternative.
- **hook-session (hermes).** Session id from payload `session_id` / `HERMES_SESSION_ID` on `on_session_start` or the first `pre_llm_call`. No transcript path: record none.
- **Notifications.** No kind-specific work.
- **Chat Mode.** Prompt route: env `HERMES_EPHEMERAL_SYSTEM_PROMPT` on the pane (new env-based route; re-apply on resume). First message `chat -q <text>`. Model `chat -m <model>`, effort `--reasoning <level>`.
- **Transcript.** Opencode-style: shell out to `hermes sessions export --format jsonl --session-id <id> -` and map `messages[]` (skip `tool`, render tool calls as activity).
- **Resume / Closed Sessions.** Keep `--resume <id>`; no-id fallback `-c` (most recent in cwd).
- **Message jump.** REPL is inline: standard.
- **Skills.** Catalog is right; project roots only count when trusted in `skills.trusted_project_dirs`.
- **Prompt gate / delivery.** **tmux delivery needs a ≥100 ms gap between the paste and Enter for hermes** (the one-line chain loses the Enter). herdr `agent.prompt` is fine. Generic `launch_pending` gate otherwise.
- **tmux launch.** `executable = "hermes"` (classic REPL); no isolation flag.
- **Agent Summaries.** `hermes -z "<instruction>"` (one-shot, final text only; approvals auto-bypassed) — help, not run.
