# OpenCode 2 server: probe for a chat Backend (Nov 2026)

Status: probe and assessment only, nothing built. It follows the runtime scan in [`runtime-alternatives-2026-11.md`](runtime-alternatives-2026-11.md) (Mike's pick: OpenCode V2 right after Codex) and the Codex Backend in [`../design/codex-backend.md`](../design/codex-backend.md).

**Method.** OpenCode **2.2.7** (`@opencode/cli`, `opencode.ai/v2/install --version 2.2.7`), linux x64, probed on **2026-11-11** in a scratch Ubuntu 24.04 container on a scratch Docker host (`rtprobe-oc2`, removed afterwards): OpenSSH 9.6p1, tmux 3.4, and the harness lab's mock model (`scripts/harness-lab/mock/server.js` plus a local `WAYCAR_ASK` token that calls the `question` tool). No real accounts or model tokens. OpenCode 1.19.5 was installed for a second user only to compare detection. **live** means observed in that container; **source** means review of the `v2.2.7` tag (`packages/cli`, `packages/client`, `packages/server`, `packages/core`); **schema** means `packages/protocol/openapi.json` at the named tags; **docs** means `services/site/src/docs/content` at `v2.2.7`.

The container ran with no init process, so an exited server stayed a zombie and `opencode service stop` failed with `Server process … still running` after 10 s. That is a container artifact, not Host behavior; the restart check below used SIGTERM and `service start` instead.

## Load-bearing OpenCode 2 facts

- **O1 — Two products, one command.** OpenCode 1 is npm `opencode-ai` (latest 1.19.5, 2026-10-28; `opencode.ai/install`). OpenCode 2 is npm `@opencode/cli` (2.2.7; `opencode.ai/v2/install`); Homebrew's `opencode` formula is 2.2.7. Both install `~/.opencode/bin/opencode`; V2 adds an `opencode2` shim, and "the V2 curl installer replaces the V1 binary" (docs, `migrate-v1.mdx`). `opencode --version` prints `opencode v2.2.7` on V2 and `1.19.5` on V1. npm last month: `opencode-ai` 14.8M, `@opencode/cli` 2.44M; Homebrew 47.3k installs/30d. Live, npm registry, formulae.brew.sh.
- **O2 — Detection starts nothing.** `opencode --version` and `opencode service status` started no process and opened no port. `service status` prints the URL or `stopped`, exits 0 either way, and took 53 ms. It is `Service.discover`: read the registration file, health-check `/api/info`, never spawn (source: `cli/src/commands/handlers/service/status.ts`, `client/src/effect/service.ts`). Both commands create empty `~/.config/opencode` and `~/.local/state/opencode` folders. V1's `service status` prints help and exits 1. `opencode api` "may start the background service" (docs): never call it. Live.
- **O3 — One shared server per user, started by any client.** `opencode service start` returned in 0.2 s, printed `http://127.0.0.1:49374` and left `opencode serve --service` reparented to pid 1. Every client (TUI, `run`, `mini`) starts the service when none is running: a TUI in a tmux pane spawned `serve --service` as its child, and the server outlived the TUI. A second TUI joined it (no second server). Service mode never exits on idle; it ends only on stop or restart (source: `cli/src/server-process.ts`). A Location (one per working directory) unloads after 60 min idle (source: `core/src/location-activity.ts`). Live.
- **O4 — The server inherits the starting client's environment.** Started by a TUI in tmux pane `%0`, its environ carried that pane's `TMUX`, `TMUX_PANE=%0` and `PWD`; service mode then changes to `$HOME` (source). Live.
- **O5 — TCP only.** HTTP/1.1 on `127.0.0.1:49374` (Linux and macOS default; 28894 on Windows; `opencode service set hostname|port` changes it). The server binds host:port only; there is no Unix-socket option (source: `server/src/process.ts`). The URL is in the registration file. Live.
- **O6 — Password.** HTTP Basic, user `opencode`. The password is in `~/.local/state/opencode/service.json` (`{id, version, url, pid, password}`) and `~/.config/opencode/service.json`, both mode 600 and owned by the user; it is generated at the first service start and stays the same across restarts. No auth gives 401 `{"_tag":"UnauthorizedError"}` with `www-authenticate: Basic`; the password as a Bearer token is also 401. Live.
- **O7 — Over SSH.** `ssh -W 127.0.0.1:49374` (direct-tcpip) works with `AllowTcpForwarding local`; `AllowTcpForwarding no`, `AllowTcpForwarding remote` and `PermitOpen none` refuse it (`administratively prohibited`), and `PermitOpen 127.0.0.1:49374` allows it. SSE streams through the channel unbuffered. OpenSSH 9.6p1, live.
- **O8 — Health.** `GET /api/info` returns `{version, pid, hostname, urls, paths, capabilities}`. It exists since 2.1.0 (schema). Live.
- **O9 — Desk sessions are visible.** A plain `opencode` TUI's session appears in `GET /api/session` with `location.directory` set to the TUI's folder and no `metadata` field at all (the first probe's `metadata: null` was `jq`'s projection of a missing key; the contract check pins the omission). Live.
- **O10 — Inventory.** `GET /api/session` returns `{data, cursor}`, newest first, 50 by default, with filters `directory`, `parentID` (`null` for top level), `archived` and `search`. Without `archived` the list includes archived sessions; `archived=false` excludes them and `archived=true` includes them (contract check). Create, get, permission and form responses wrap their value in `{data}`; `PATCH` answers 204. `GET /api/session/active` returns `{data: {<sessionID>: {type: "running"}}}`, only while a turn runs. Session info carries `title`, `agent`, `model`, `metadata`, `location`, `outcome` and `time.{created, updated, busy, idle, viewed, archived}`. Sessions are durable (`~/.local/share/opencode/opencode.db`) and never unload. Live, schema.
- **O11 — Waycar picks the session id.** `POST /api/session {id, title, metadata, location: {directory}}` accepts a client-chosen id matching `^ses`. Repeating the same create returns the existing session (200, title unchanged), so a create is idempotent. `metadata` is free JSON and reads back from get and list; `PATCH /api/session/{id} {metadata}` emits `session.metadata.updated`. Desk sessions have no `metadata`. Without `location` a session lands in the server's home folder. Live.
- **O12 — Pane join by construction.** `opencode --session <id>` opens that session, or creates it with exactly that id at its first prompt; `--prompt <text>` sends a first message. Both appear in the pane's `ps` arguments. A TUI on an API-created session shows API prompts live and their permission dialog. V2 has no `-m`/`--model`: `opencode -m mock/mock-model` prints help and exits 1. Live.
- **O13 — Prompt.** `POST /api/session/{id}/prompt {text}` returns the inbox item (`delivery: "steer"`) in about 0.13 s, before the turn runs; the turn runs in the server. A prompt to a running session is enqueued and delivered at its next step. Live.
- **O14 — Events.** `GET /api/event` is one SSE feed for every Location: `data:` lines only (no `id:` field), first frame `server.connected`, an immediate `: heartbeat` comment and then one every 15 s (source: `server/src/handlers/event.ts`), `types=` (repeatable) filters on the server, and nothing is replayed. Session events carry `durable: {aggregateID, seq}`. A turn reads `session.inbox.enqueued`, `session.execution.started`, step, text and tool events, then `session.execution.succeeded`, `failed` or `interrupted`; a TUI showing the session adds `session.viewed`. `GET /api/experimental/session/{id}/log?after=<seq>&follow=true` is a per-session durable catch-up log (schema; not exercised). Live.
- **O15 — History.** `GET /api/session/{id}/message` pages newest first with a cursor. Items: `user {text}`, `assistant {content: [text | tool …], finish, tokens}`, `idle {outcome}` and `synthetic {text}`. Live.
- **O16 — Interrupt.** `POST /api/session/{id}/interrupt` returns `{interrupted: true}` and emits `session.execution.interrupted` with `data.reason: "user"`; the idle item's outcome is `interrupted`, and the session's `time.idle` is the event's `created` (contract check, 2026-11-12). On an idle session it returns `{interrupted: false}`. A prompt enqueued before the interrupt stays undelivered in `GET /inbox` and goes out with the next prompt. Live.
- **O17 — Permissions.** An `ask` rule raises `permission.asked {id, sessionID, action, resources, save, source: {messageID, id}}`, also listed by `GET /api/session/{id}/permission` (and per Location by `GET /api/permission/request`). `/active` still says `running`; there is no waiting flag. `POST …/permission/{id}/reply {decision: "once" | "always" | "reject"}` returns 204 and emits `permission.replied`; a second reply returns 404 `PermissionNotFoundError`. A `reject` ends the turn: `session.execution.interrupted` with `data.reason: "shutdown"`, the tool's state `error` (`aborted`), no `idle` history item and no `time.idle` on the session (its `outcome` stays null), unlike an explicit interrupt (contract check; reason and `time.idle` added 2026-11-12). A pending request survived a 20 s client disconnect and was answered from a new connection. A TUI's Enter on an API-raised request reached API clients as `permission.replied`. Live.
- **O18 — Questions are Forms.** The `question` tool creates a Form: `form.created {form: {id, sessionID, title: "Questions", metadata: {kind: "question", tool}, fields: [{key: "q0", title, description, type: "string", options: [{value, label, description}], custom: true}]}}`, also listed by `GET /api/session/{id}/form`. `POST …/form/{id}/reply {answer: {q0: "Blue"}}` returns 204 and emits `form.replied`. Live; source: `core/src/tool/plugin/question.ts`.
- **O19 — Disconnects.** Dropping the event stream, or killing the TUI's pane (SIGHUP) mid-turn, does not cancel the turn; it completes in the server. Live.
- **O20 — Server restarts.** After SIGTERM mid-turn and `service start`, the URL and password were unchanged; running turns resumed by themselves after a synthetic message ("The server restarted while you were working. Continue from where you left off without repeating completed work."), and pending permission requests were cancelled (tool error `aborted`, "Interaction cancelled because the location shut down"). A TUI newer than the running server restarts it (`mismatch: "replace"`, "Restarting background server (version mismatch)…"; source: `cli/src/commands/handlers/default.ts`), so an upgrade interrupts other clients' turns. Live, source.
- **O21 — Plugins run in the shared server.** V1 plugin implementations do not run on V2 (docs). V2 loads `.js`/`.ts` files from `~/.config/opencode/plugins/`, where Waycar's Host Tools put today's opencode plugins: both Waycar files loaded as `active` and did nothing (their V2 `setup() {}` is empty on purpose). A V2 plugin runs inside the server process with the server's environment (`TMUX_PANE=%0` for every session), loads once per loaded Location, and every instance's `ctx.event.subscribe` receives every global event: three instances each logged the same `permission.asked`. Plugin files hot-reload. Live.
- **O22 — Transcript CLI moved.** V2 has no top-level `export` (it prints help); `opencode session export <id>` prints the JSON. Waycar's chat reader runs `opencode export <id>`. Live.
- **O23 — Config.** V2 reads V1 config files from the same paths; native V2 permission rules are `permissions: [{action: "shell", resource, effect: "ask"}]` (V1: `permission.bash`). Docs.
- **O24 — Versions and stability.** 2.0.0 shipped 2026-09-11; 46 releases followed to 2.2.7 (2026-11-10). The OpenAPI document calls itself `version 0.0.1`, "Experimental HttpApi". Paths grew 119 (2.0.0, 2.1.0), 130 (2.2.0), 139 (2.2.7). Every endpoint above exists in 2.1.0 (`PATCH /api/session/{id}` and `/api/info` arrived in 2.1.0); 2.1.0 also moved tool and message data (`tool.native`) and removed `session.compacted`. Schema diff, CHANGELOG.
- **O26 — Instruction entries reach the system prompt.** `PUT /api/experimental/session/{id}/instructions/entries/waycar-chat-prompt {value: "<text>"}` answers 204, `GET …/instructions/entries` lists it, and the next turn's request to the model carries `<context key="waycar-chat-prompt">\n<text>\n</context>` in its `system`, after the `<env>` block (mock log `GET /_log`). `model: {id, providerID}` on create sets the session's model. `GET /api/session?parentID=null&archived=true` lists only archived sessions, each with `time.archived`; `session.archived`'s event `created` is that time. Live, OpenCode 2.2.7, `rtprobe-oc2`, 2026-11-11.
- **O25 — TUI.** The V2 TUI still draws the `┃` input box (1.5 s after launch, warm) and runs as process `opencode`. Live.

## Today's opencode support on an OpenCode 2 Host

What Waycar does today was built for OpenCode 1 (`harnesses/opencode.md`, 1.19.0). On a V2 Host:

- Status Hooks and the Chat Prompt extension load but do nothing (O21), so tmux status falls back to the screen and a Chat Mode Agent never gets its Chat Prompt.
- The chat reader's `opencode export` fails (O22), so the transcript is empty.
- A Chat Mode launch with an OpenCode model set in Settings passes `-m` and exits at once (O12).
- The `┃` gate, `--prompt` and `--session` still work (O12, O25).

Not checked: herdr's opencode integration on V2 (also a V1 plugin, so probably inert), macOS, a real model, subagent sessions, the `always` decision, the experimental log endpoint.
