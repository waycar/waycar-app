# Apple Watch companion that relays through the iPhone

_2026-10-12, accepted: design in `docs/design/apple-watch-v0.md`, branch `Apple-Watch-v0`, issue #193._

Mike's story is "glance at my Agents from the wrist, read what one just said without sound, and talk back to it". The watch app is a companion to the iPhone app, modelled on Waycar in CarPlay (ADR 0028): the same list, sort, status words and sources, but shown silently instead of spoken. A paired iPhone is required.

Decisions:

- **The iPhone relays everything.** The watch never opens SSH or mosh and links no SSH, terminal or analytics packages. Every read and action goes to the iPhone app over WatchConnectivity: Watch State (Hosts, Agent titles, statuses, status ages, per-Host condition) through `updateApplicationContext`; requests (refresh, Latest, Blocked prompt, Allow/Deny, send, voice) through `sendMessageData`, each with a message id the iPhone dedupes. The reply only acknowledges receipt, before any SSH work; the outcome (sent, not sent, unknown, kept as draft, no words) arrives later through `transferUserInfo`, keyed by id, so it survives the watch app going to the background. Nothing is retried on its own; "Try again" is an explicit tap and only after a definite not-sent.
- **Headless iPhone start.** A WatchConnectivity wake starts the app model without a window (`AppActivitySource.watch` joins `.phone` and `.carPlay` in `AppActivityCoordinator`), so a request works with the iPhone app closed or the phone locked. A locked phone has no readable list cache (ADR 0028) and connects fresh.
- **Voice is recorded on the watch and transcribed on the iPhone.** Waycar's own recorder shows no live text: it stops on a tap, a double tap, or 3.5 s of silence after speech; no speech in the first 8 s cancels; 60 s is the cap. The audio goes to the iPhone over WatchConnectivity, is transcribed there with `SpeechAnalyzer` and sent at once (no read-back, like CarPlay), and is deleted on both devices once the message is sent or abandoned; the sent text returns to the watch to show as sent. Voice never goes to Apple's servers. When the iPhone is below iOS 26 (no `SpeechAnalyzer`), the watch falls back to system text input (`TextFieldLink`), which shows live text and may use Apple's servers; the app says so.
- **CarPlay-parity approvals.** Allow only when `BlockedPromptClassifier.carApproval(for:) == .allow`; `.hold` offers Deny only; `.readOnly` shows "Answer this one on iPhone." and sends nothing. The command is shown in full, losslessly. A permission command containing invisible or format characters is not lossless and gets Deny only; this tightens CarPlay too. Answers go through `BlockedPromptAnswerer`'s re-read guard against the exact text the iPhone sent to the watch, kept under a prompt id; a mismatch sends nothing ("Prompt changed. Reload."), and a prompt that is gone shows "No longer waiting for approval." with Reload. Waycar never types into a Blocked prompt: no mic on a Blocked Agent ("Review prompt" instead), and text sent to an Agent that is Blocked at send becomes the Composer draft.
- **Notifications: iPhone-registered categories, guarded typed reply.** Only the iPhone app registers notification categories; the watch registers none. Below iOS 26 the Done notification's Reply is a typed `UNTextInputNotificationAction` handled on the iPhone: it requires authentication and sends only to an Agent named in the decrypted notification. If the text is definitely not sent (or the Agent is Blocked), it is kept as the Composer draft and the iPhone posts a local "Not sent to <title>" / "Kept as a draft on your iPhone." notification. An unknown outcome keeps no draft, so nothing is sent twice, and posts "<title>" / "Couldn't confirm it was delivered."; a send still running past the deadline counts as unknown. With no Console row to hold a draft, no Agent the notification names (an envelope the iPhone can't decrypt), or nothing left after cleanup, it posts "Reply not sent" / "Open Waycar and send it again.". Voice replies report their outcome on the watch.
- **No reply suffix.** Watch prompts go out as typed or spoken; the CarPlay Spoken Reply Suffix is not appended.
- **Live Activity on the watch: counts-only `.small` baseline.** The per-Host Live Activity adds the `.small` supplemental family, showing counts and "Waycar" only. This amends ADR 0014 only by adding that family; showing decrypted Agent rows on the watch is deferred until a device spike shows where the `.small` view is rendered.
  - *Amended (#189, #199):* by the user's decision for Agent Progress, the `.small` view now shows the lead count and up to three Agents (short name, progress bar, label), drawn from the same decrypted details envelope the Lock Screen rows use. Where watchOS renders the `.small` view is still unverified on a device. The watch app's own rows also carry a progress estimate (plan steps or a phase word) over WatchConnectivity.
- **Latest in full, never truncated.** *Amended (#202):* after Mike's first device test, the watch never truncates text: no ellipsis, no line limits, no "More". Titles, status lines, notices and bubbles wrap; the Digital Crown scrolls. W2's Latest is the Agent's whole last reply whenever the iPhone can read its transcript through `ConsoleStore.readChatTranscript`: every Chat Mode Agent, and any Agent of a kind the transcript reader supports (ADR 0025) while the Host reports its live agent session. Otherwise it is the Agent Summary in full. A Working Agent with a fresh Summary shows it first and the reply under "LAST REPLY". The relayed text is capped at a 48 KB byte budget, because `sendMessageData` replies have an undocumented size limit; an over-budget reply keeps its end after the plain line "Earlier text is on your iPhone." This replaces the earlier two-sentence cap with "More" and the 100-character summary cap.
- **Free.** The watch answers existing Agents and is never Pro-metered (ADR 0023).

## Consequences

- The iPhone app embeds a watchOS 11 app (`com.otreva.waycar.watchkitapp`); device builds need the watch target signed too.
- The iPhone app must answer WatchConnectivity requests while backgrounded or locked, so headless start, multi-source activity and the Keychain readability rules from ADR 0028 now serve a third surface.
- Agent titles, statuses and Host names reach the watch and are stored there in the application context; Latest text and Blocked commands are fetched on demand and held in memory only. `PRIVACY.md` gains an Apple Watch section, including the pre-iOS 26 dictation exception.
- A misheard word reaches the Agent with no review step (accepted risk); the sent text shows on the watch afterwards as the only mitigation.
- `AgentVoiceService`'s actions move into a surface-neutral action service shared by CarPlay and the watch, and `CarPlayListModel` into a surface-neutral list model; the suffix becomes optional.
- Watch features need a reachable iPhone: actions are disabled while it is unreachable, and the list shows its age.

## Considered options

- **System dictation as the default voice input**: rejected. watchOS dictation shows live text, which Mike finds harder to talk over, and may send audio to Apple's servers. It stays only as the pre-iOS 26 fallback.
- **Standalone SSH on the watch**: rejected. It would need Host keys and Notification Keys on the watch, duplicate connection and Backend logic, and drain the battery; the iPhone already holds one live Console.
- **Allow from a notification action**: rejected. The notification shows the Agent Summary, not the lossless command, so approving from it would approve unseen text. Notifications only open the Blocked screen.
- **Earlier draft (`docs/design/apple-watch.md`, branch `apple-watch`, commit `fdeb2dd1`)**: superseded. It mirrored the existing Live Activity with no new code, defaulted to Apple's dictation with a privacy note, read back dictated text before sending, and allowed approval from notifications.
