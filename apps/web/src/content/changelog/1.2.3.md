### Added

- **Ultimate conversations in the Console**: when the Ultimate agent server
  runs on a Host, its conversations show up as agents with Working and Idle
  status, grouped by project. Tap one to read it in Chat Mode and reply from
  the Composer. Nothing to install on the Host; Waycar reaches Ultimate over
  your SSH connection.

- **Welcome Allowance**: no Launch limit for the first 30 days after you connect your first Host, then 10 Launches per rolling 30 days. Settings shows the end date and time, with a dismissible reminder five days before. Watching and steering running Agents stay unmetered.

- **Tidier Host page**: the Preflight checks and Status Hooks on a Host's
  page now collapse into one summary row each — a green checkmark when
  everything passes, a yellow warning for non-blocking findings, a red X for
  a blocking failure. Tap to expand the full details; a blocking failure
  expands itself. The Status Hooks summary now warns only about agents that
  are installed on the Host; agents you don't use list as "Not installed"
  with no warning. (#386)

- **Mark as Unread on an agent's screen**: the More menu on an Idle agent's
  screen now has Mark as Unread. It marks the agent unread and takes you back
  to the Console, where the agent lists as Done again.

- **Hosts that run herdr-core**: Waycar now works with a Host that runs
  herdr-core, the runtime under the Herdr app (version 0.1.10 or later).
  Every terminal it runs shows in the Console, agents and plain shells, with
  status for the agents that report it to herdr-core (Claude Code and Pi);
  the rest read Unknown. You can open a terminal, send prompts and keys from
  the Composer, and close it. If herdr-core restarts, the rows stay. Not
  there yet on herdr-core: worktrees, new Workspaces, renaming, mosh, and
  Windows Hosts.

- **Notifications, Live Activities and Chat Mode on herdr-core Hosts**: install
  Waycar Host Tools on a Host that runs herdr-core and you get banners and push
  notifications when an agent is Blocked or Done, Live Activities, Agent
  Summaries, and Chat Mode for agents that report through the hooks. Waycar's
  Install and Update buttons now work for a Host that has only herdr-core, and
  its install message no longer says "for tmux". Agents that never report
  status to herdr-core get no push and no Live Activity row.

- **Start agents on herdr-core**: New Agent now works on a Host that runs
  herdr-core. It asks for the agent and a folder; Waycar checks the folder,
  starts the agent there as a new terminal and opens it. The agent is found
  the way your login shell finds it, so one installed in `~/.local/bin`,
  nvm or cargo starts even when a plain SSH login can't see it. A first
  message waits until the agent reports it is ready, or, for an agent that
  never reports, until its input shows. Resuming a Closed Session starts a
  new terminal of the same agent in the same folder. A launch counts toward
  the free allowance like any other, and so does a command you type into a
  shell row. A program the Host doesn't have says "<agent> is not installed on
  this Host, or is not on its PATH".

- **Install herdr-core from the app**: a Host with no tmux, Herdr TUI or
  herdr-core now offers three installs on iPhone and iPad: Install Herdr TUI,
  Install tmux, and Install herdr-core. Install herdr-core shows the exact
  command, the account and the Host, then runs herdr-core's installer over
  SSH, puts `herdr-core` in `~/.local/bin` with no admin rights, and connects
  once Waycar finds it. The old Install herdr button is now Install Herdr TUI.
  When it fails, Waycar names why: no curl, no tar, the installer can't be
  reached, or a system herdr-core doesn't run on.

- **Move Hosts off Node**: a Host that still runs the Node version of the
  Waycar plugin now shows "Update Waycar to stop needing Node" in the Console,
  and an Update button in Host detail. One tap runs the update the app already
  has. The new native tools replace the Node ones, so Waycar no longer needs
  Node on that Host; the old Node files Waycar installed are removed, and your
  own Node, your pairing, keys and settings stay as they are. The sheet says
  before it starts that Codex may ask you to review Waycar's hooks once in
  `/hooks`. Not now hides the prompt for 14 days, once more after that, then
  for good, and a failed update says when the old version is still installed.
  Hosts you leave alone keep working as before.

- **Host Tools install on a Host that runs herdr-core**: the install command
  now sets up a computer that has only herdr-core (no herdr, no tmux), and its
  agent hooks run inside herdr-core terminals: a Blocked or Done change sends
  its push and the Live Activity updates, for agents that report their status
  to herdr-core. The messages the installer prints when it finds no usable
  backend now name herdr-core too.

- **Push notifications and Live Activity without Node.js**: the Host Tools'
  hook runtime now also runs as native code. On a Host with no Node.js, a
  Blocked or Done change sends its push, and the Live Activity updates, as
  before, with the Agent Summary, the Chat Mode reply and the plan-step
  progress the Node.js version carried. A Host that has Node.js keeps running
  what it ran.

- **Agent Summaries without Node on the Host**: a tmux Host with no Node.js
  now refreshes Agent Summaries, and so does herdr's `refresh-summaries`
  action. The refresh runs in the native `waycar` file the installer already
  puts at `bin/waycar`, and it keeps reading and writing the same files, so a
  Host that switches between Node and the native file loses nothing.

- **Host Tools install, pair and hooks without Node**: a server with tmux or
  herdr and no Node.js now installs the Host Tools, shows the Pairing Code QR
  and installs the agent status hooks. `waycar` is one native file for the
  Host's system, so `install.sh` no longer stops when Node is missing. The
  status hook also works on images with no `ps` (Debian slim, Alpine).

- **Install herdr or tmux from New Agent**: on a Host with neither (or with a
  tmux older than 3.2 and no herdr), New Agent says what is missing instead of
  leaving Start grey with no reason. Install herdr (no admin rights, one file
  in `~/.local/bin`) leads. Install tmux appears when the Host has a package
  manager Waycar can run. Waycar asks every time, shows the exact command and
  what it changes, then runs it over SSH and shows the output as it arrives.
  Hide keeps it going, and reopening New Agent shows its progress. Waycar says
  "found" only after it checks the Host again. A failure names its reason,
  with Copy Command, How to install and Check Again. Default Shell shows as
  unavailable on such a Host, and the Workspace row reads "None found". The
  Console's Host banner now reads "No tmux or herdr on this Host. Tap to set
  up." and opens the same panel.

- **Install Waycar Host Tools from the Console**: a Host without the Waycar
  plugin shows an "Install Waycar Host Tools" row with Install and Not now,
  whatever backend it runs. Install opens the same consent screen as an
  update. Not now hides the row for 14 days; it returns once. Host detail has
  a "Remind me to install Host Tools" switch per Host. Off never shows the
  row.

- **Try Waycar without a Host**: first-run setup includes a labelled Sample
  with example Blocked, Done and Working agents. Browse it offline, then
  choose Connect your machine to get the install command. The sample is
  read-only, uses no Launches, and disappears when you add a Host. (#314)

- **Share the install command**: on the setup screen, Share sits beside
  Copy on the install command and opens the share sheet, so you can send it
  to the computer you want to add from Messages, Notes, AirDrop or Mail.
  Only the command text is shared.

- **Reach status in the install command**: Waycar plugin 1.5.1 prints whether
  it finds Tailscale before pairing. The check installs nothing. Without
  Tailscale on the Host, it links to the guide for using one subnet-router
  device at home. (#310)

- **Where pairing stops, measured anonymously**: if you have turned on "Share
  usage analytics", Waycar counts when Scan to Pair starts (by scan or paste)
  and the step where it is given up, so we can see where pairing loses
  people. The App Store build sends no failure reasons.

- **Return visits, measured anonymously**: if you have turned on "Share usage
  analytics", Waycar counts at most once a day that the Console was used,
  with Host, runtime and Agent counts as ranges; the first time you reach a
  few milestones, such as a Host connecting or a first message to an Agent;
  and how a Host was added (scan, paste or manual). Only fixed words and
  ranges are sent, never Host names or content, and nothing is sent while
  that switch is off.

### Changed

- **Richer Ultimate chats**: Read full-width assistant replies, answer question
  cards with a tap, and open branches or failed conversations from their cards.
  Tool steps stay compact, a working indicator tracks the turn, and Stop lets
  you interrupt it. On iPad, a left rail keeps branches close by. (#16477)

- **Ultimate projects stay together**: Each project's @ultimate lead keeps
  its branches folded, while other standing Agents keep their own cards.
  Tap Show to reveal branches, then open each branch's own chat. Working
  and needs-you counts appear on the card and in Live Activities. Branches
  waiting for your reply show a Blocked label, with replies sent through
  native chat.

- **Both herdr runtimes, one Console**: Hosts with Herdr TUI and Herdr Core
  now show Agents from both together. Pick **Herdr TUI**, **Herdr Core** or
  **tmux** right in New Agent when creating a Workspace; your choice is
  remembered per Host. Host settings only control which runtimes are
  visible, and core notifications follow core visibility. Cards no longer
  carry an always-on runtime badge: add the optional `runtime` field
  (Herdr TUI, Herdr Core or tmux) in Settings › Agent List Fields when you
  want it. (#5160)

- **Herdr Core workspaces keep their desktop names**: Workspaces and tabs on
  a Herdr Core Host now show the Herdr app's own space and tab names (read
  live from the app's layout), falling back to the start folder's name for
  terminals the app doesn't manage. (#9570)

- **New Agent on a Host without agents**: when no agent CLI is detected, the
  sheet now preselects Default Shell with a short note instead of showing a
  "No Agents Found" error, so Start always works. Detect Again stays for
  after you install an agent.

- **Newer Waycar plugin shown on the Host page**: a Host whose Waycar plugin
  still works with the app but is older than the latest no longer reads "Up
  to date". Its page shows the newer version, such as "2.3.0 available", with
  the update button. Updating is optional; nothing else asks.

- **Louder dictation waveform**: While you talk, the Composer's voice
  waveform now rises much more for normal speech, so it's easy to see
  Waycar hears you.

- **Host Tools need no Node.js**: from 2.0.0 the Host Tools are one native
  program for Linux (x86_64, ARM64) and macOS (Apple Silicon, Intel), so a
  Host needs only herdr or tmux 3.2 or later, plus curl and tar to install.
  No Node, npm, nvm or Homebrew. A Host that installed the Node version moves
  with one rerun of the install command, which Waycar runs for you; your own
  Node and npm are left alone, and Codex asks for one hooks review.

- **Pairing checklist**: your home network and Tailscale IPv4 addresses start
  checked when present. IPv6 addresses remain available to select. (#310)

### Fixed

- **No CarPlay settings on iPad**: CarPlay settings no longer appear on
  iPad, where CarPlay isn't available. CarPlay works with iPhone only, on
  iOS 26.4 and later.

- **Host Tools offers stay answered after a reinstall**: Not now, a turned-off
  "Remind me to install Host Tools", and a dismissed plugin update row now
  sync with iCloud Sync, so they come back with your Hosts after you delete
  and reinstall Waycar, and apply on your other devices too.

- **Duplicate Agent launches on tmux 3.4**: the check for other Agents already
  running in the same directory read tmux's pane list with a tab separator,
  which tmux 3.4 prints as text, so it saw no tmux panes. It now uses a
  printable separator.

- **Agy and Cline approval dialogs on tmux 3.4**: the Host Tools now notice a
  permission or question dialog there and mark the agent Blocked. They did
  not before, because tmux 3.4 changes the control character the watch used
  to read the pane.
